## 状态说明

- **提出**：形成想法或待确认方向。
- **选定**：完成方案选择，但尚未实现。
- **已实现**：能力已经进入当前项目。

## 2026-08-19

### Agent 单权威持续收敛治理落地

- 当前仓库新增专用的 Agent 架构治理范式，将后续变化分为直接修改、模块变更与架构替换三级；只有改变 Command、Goal、Plan、SemanticResult、PublicAgentTurn、API、State 或前后端共享合同的变化才启动 Replacement Slice，避免普通功能修改被过度架构化。
- 单一生产权威、无运行时兼容桥、版本级回退、共享公开合同、证据先于完成声明与隐私边界被固定为不可绕过规则。环境、授权和跨责任区门禁可以延期，但必须保留原因、证据、恢复条件、下一动作、禁止声明和复查期限，不能把 `WAIVED` 记作 `PASS`。
- 当前权威与延期项由机器可读状态账本维护，项目专用 Architecture Guardian 指导后续 Agent 主动重查恢复条件；状态校验已进入发布门，存在未关闭延期项或被绕过硬规则时不能把整体状态标为完成。当前状态：**治理范式、项目 Skill 与机械门已落地，账本无未关闭延期项**。
- Guardian 改为当前仓库每个任务默认执行轻量 Bootstrap：非 Agent 架构任务以 `NOT_APPLICABLE` 立即退出，Level 1/2 与已批准 Level 3 自动继续，只有适用或边界不确定时才加载完整架构上下文。该变化使治理默认存在，但不把普通开发变成架构审批。
- Guardian 与更新代码、真实测试或已批准设计冲突时，只降级冲突规则并继续项目工作；漂移复用现有 `deferredItems` 记录为 `GUARDIAN_DRIFT`，不新增状态机或独立账本，隐私与外部授权边界继续保持硬约束。

### General 与 Cross-domain 能力完成单链替换

- General 改为专用 typed Model Port：Request 直接表达 topic 或 comparison subjects/dimensions、depth、audience 与 absolute deadline；一次模型调用后进行严格 JSON 解码和完整结构校验，合法结果直接成为最小 `GeneralSemanticResult`，再独立生成 `GeneralPresentation`。
- Cross-domain 只接受一个 General 与一个 Portfolio SemanticResult，以 Plan 固定的 concept anchor 选择通用 definition/mechanism 和已验证项目事实，确定性生成「通用原理 / 项目实例 / 二者关系」三段 Presentation。Portfolio 来源不会被标到 General 段落。
- 删除万能 Conversation Model 的 classify/generate/review/suggest/summary、空 ConversationWindow/Route 协议、General 大字段 Material pipeline、substring 关系策略、Cross-domain 模型表达及旧 mock Provider Eval 兼容链。当前状态：**Slice 4 已实现并完成本地全量验证，未部署**。

### PublicAgentTurn、Agent State 与无版本 API 完成后端原子替换

- 后端公开合同收敛为五种 PublicAgentTurn 与两种 Presentation，按 User Goal 顺序只投影 fulfillment 结果；来源只存在一个 catalog，General/Portfolio/Derived 支持不互相冒充。
- Turn 生命周期统一 claim、HMAC fingerprint、active cancel、complete/replay 终局门；最终公开快照与 Context/Clarification mutation 使用 AES-GCM 加密并在 PostgreSQL 单事务提交，固定短 TTL，正文之外不保存问题、Prompt、SemanticResult 或原始 Evidence。
- 首次生产资源固定为 `/api/agent/turns` 与 `/api/agent/conversations/current`；旧 `/api/v2`、ConversationAnswer DTO/Mapper、Completion Receipt、Context Facade/MOST_RECENT 与双 Codec 已删除。
- Goal/General 模型调用共享 typed StructuredModelTransport；旧阶段 Eval/HTTP answer client、Selection service 和重复传输 DTO 被删除，Eval/benchmark 不进入最终 JAR。
- Frontend 已切换到四条无版本 API、Bearer/sessionStorage、取消/清除/澄清与 closed PublicAgentTurn 组件树，并删除旧 answerTypes、stp mapper/fallback、Plan/Execution/Context 兼容组件和巨型测试矩阵。
- 最终联合结果：Backend 879 tests（0 failure/error，5 个非 Docker 条件 skip），PostgreSQL 16/pgvector Testcontainers 与 Flyway/Repository 实际通过；Frontend 417/417、vue-tsc/Vite build、Spring Boot package、privacy 与生产源码零引用门通过。旧 E2E fixtures/mocks 已删除，最终 packaged-JAR 桌面/移动 Browser E2E 6/6 通过；真实 DeepSeek 应用 canary 返回 `ANSWER/COMPLETE`，Goal 解释与 General 生成两个 Provider operation 均成功。当前状态：**Slice 0—6 已完成本地实现与最终联合验证，未 push、未部署**。

## 2026-08-17

### Agent 后端确定性闭环与 P1/P2 隔离收口

- 修复推荐与计划结果的完整性语义：全部主任务仅部分回答时顶层计划保持 `PARTIAL`；推荐完成任务公开请求数、实际数、候选范围、选中主体、未满足约束和原因码，使前端可按真实 `1/3` 等状态展示，不再依赖卡片数量推断。
- 推荐证据门禁从通用“每项最多两组证据”中拆出公开交付证据的 1—5 项合法上限；三项目推荐可返回三项，候选与已选证据零交集则安全返回 `NOT_SUPPORTED + PORTFOLIO_RECOMMENDATION_EMPTY`，不再落入执行拒绝。
- P1/P2 隔离编译器补齐 compiled/clarification-required/rejected 三态；未审核别名、页面提示或确认依据不足进入受控澄清，虚构/非公开主体与非法结构继续拒绝。fallback 改为只消费公开主体的 reviewed alias，提议与锚点补齐结构值语义。
- 页面引用标记资源移入 `public-data` 运行边界；随包验收脚本新增 `-SkipPlaywright` 和 commit/JAR SHA-256/构建时间/PID/端口/contentVersion 绑定，并增加噪声输入、三项目推荐及安全摘要检查。
- DeepSeek V4 Flash 已通过本地最终候选的真实外部 Provider canary；后端 1256 项测试通过（21 项 Docker 环境条件跳过），前端 723 项测试及生产构建通过，确定性与真实 Provider 随包冒烟均通过。密钥只从进程环境读取，验收输出不记录问题、回答、Prompt、Token 或原始模型响应。当前状态：**已实现并完成本地验收，未部署**；`MODEL_LED` 主链、P3-P8 与生产默认模式仍未启用。

### Agent 前端体验闭环（回答优先、证据按需、执行降噪）

- Agent 对话页信息层级按「答案优先」重组：回答正文与一行「依据 N 组已审核公开证据」来源摘要成为主内容；任务摘要、执行概览与回答构成三个执行部件统一为正文之后的收尾组，成功默认收起，部分完成/失败自动展开并显示任务名；阶段状态不再使用绿色，访客可见文案不再出现 `ANSWERED · EVIDENCE_COMPOSITION` 等协议枚举（译为「已根据公开证据整理回答」等）。
- 证据引用改为公开编号与标题（如「E-01 · SQL 审计工具交付证据集」），内部 Evidence ID 不再出现在界面文本；证据工作台状态文案中文化，明确区分「聚焦当前回答」与「公开证据目录」。
- 噪声输入（纯数字等）只显示澄清卡与三类安全入口（了解/比较/推荐项目），不再渲染验证标签或执行状态；纯数字、过短输入不再成为会话标题，占位「待补充问题」可被后续有效问题升级，完整问题保留为悬停辅助信息。
- 推荐数量完整性按新契约兼容消费：`requestedSize/actualSize/reasonCodes` 齐全时展示「找到 1/3 个符合条件的项目」+「部分完成」+服务端原因+唯一恢复操作「放宽条件重新推荐」；字段缺失时使用中性文案，不根据卡片数量宣称全部满足。
- 自由追问自动携带最近一轮后端签发的可信续接句柄（contextReference），「第二个呢」等指代由服务端在可信 Context 内定位，不依赖页面默认项目；推荐后的补全建议优先围绕当前结果集合。
- 当前状态：**已实现，未部署**。推荐数量完整性等新契约字段在后端确定性路由闭环上线前由合同 fixture 验收（澄清、1/3 部分推荐、证据聚焦与句柄续接场景）；不改后端协议语义，旧 Evidence ID 回退等兼容代码保留。
- 相关设计：[Agent 前端体验闭环交接设计](superpowers/specs/2026-08-17-agent-frontend-experience-handoff-design.md)

- 项目被定义为面向公开访问者的实习作品集 Agent，而不是连接私人知识库的个人 Copilot。

### 阶段一：Agent 运行时接入作品集硬路由与无状态推荐

- `/api/v2/answers` 已在通用模型生成前接入 `PortfolioTaskResolver` 与 `PortfolioIntelligence`：确定性作品集规则、Project/Case 上下文、推荐上下文，以及外层路由判定为作品集或混合意图时，统一转入新检索 seam。
