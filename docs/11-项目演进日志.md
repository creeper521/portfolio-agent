### Agent 失败恢复与项目讨论状态补完

同 requestId 重试改为复用页面内存中的完整提交快照；Clarification V5 以 requestId reservation 仲裁并只在 terminal settlement 中消费。Project Discussion 修复单候选不确定路由、来源 TTL 裁剪与 PostgreSQL replacement parity；V6 提升 Session revision 为公开状态世代，成功 Turn 与 replay 直接返回当前权威 summary，前端删除热路径二次 GET 并按 revision 单调应用。
已结算的 `DISCUSSION_INTERPRETATION_UNAVAILABLE` 保持同 requestId 幂等重放，同时投影原输入的新 requestId 重试 action 和 closed `EXIT_CONTEXT` 退出 action，不在 replay 中隐式重调 Provider。

讨论 TTL 独立为默认 20 分钟，使有效 Session 内的 EXPIRED、重进和开始新话题首次可达。确定性全量、V1—V6 Testcontainers、模型关闭 packaged PostgreSQL、桌面/移动 short-TTL lane 与隐私门已通过。真实 Provider 门已获授权并执行：聚合指标曾验证 CONCISE/STANDARD/DETAILED 各 3/3，但后续 DeepSeek 语义路由整体进入快速 unavailable，GLM 响应也未通过闭合合同；最终完整绿灯未取得，因此架构状态保持 IN_PROGRESS。

## 2026-08-24

### Goal Provider Draft 锚点收敛与 Qwen 实测恢复

经 Qwen 实测定位，Goal v2 草案的 goal 级 `inputText`「精确唯一子串回显」义务是线上间歇性 `DRAFT_ANCHOR_NOT_FOUND` 整稿拒绝的来源：Provider 偶发带回标点或空白的非精确回显，而 canonical 锚点本就由服务端机械派生。据此收敛契约：`goal.provider-draft.v2` 不再要求也不接受 goal 级 `inputText`，canonical `inputAnchor` 改由服务端从受信 currentInput 前缀（≤256 字符、起点 0）确定性派生；主体/主题/概念级锚点仍由 Provider 语义选择并保持「已审核别名 + 唯一精确子串」校验。锚点拒绝诊断增加封闭来源后缀（只命名白名单字段，不回显 Provider 文本），提示词同步明确「明示计数即解析 requestedSize，仅在完全没有数量时才允许 REQUESTED_SIZE 澄清」。方向上这是对既有「锚点位置由服务端机械派生」教义的补全：删除 Provider 不必要义务，而非引入 repair、重试或 fallback。

Qwen 实测在该收敛后恢复执行：Goal 侧探针与 L4 两轮草案矩阵共 40 次 TURN_INTERPRETATION 全部无草案拒绝，此前同输入的锚点整稿拒绝消失；同 lane 的 General 侧因正文质量与 Provider 限流整体 FAIL，GLM 侧探针因持续限流记 BLOCKED，两家独立矩阵与 GATE-19 双模型 lane 仍待执行。

### Provider 诊断实验室与离线认证门

新增固定三档合成 corpus、repo 外精确 24 小时 raw artifact 实验室、v3/v4 双回放、认证报告与两遍盲审证据链。所有入口复用同一个 raw-root 硬围栏，在 ACL、枚举或写入前拒绝宽根、repo 关系、reparse point 和无 marker 目录；正式证据只接受由实际 endpoint 内部派生的 `REAL_PROVIDER`，测试环回不能进入 PREPARE 或形成候选通过。安全/身份/权限、缺 core 与 canonical false acceptance 均由实际执行当前生产边界的 guard artifact 计算，不使用硬编码零；`jdeps -R` 从实际编译产物机械生成 producer 闭包并绑定源码/资源，source-drift 负例只修改严格隔离的临时源根。旧 v3 基线绑定批准时点的 Git blob snapshot、可执行基线与 golden behavior matrix。

复审期间由机器 guard 真实暴露了既有链缺少 secret-like 出站预检，以及 2xx response `model` 未与冻结 binding 对齐；随后在唯一 Transport seam 补入高置信文本值扫描和响应模型身份校验。标签赋值、standalone API key 与 PEM 私钥标记在 HTTP 与 Provider 事件前失败关闭，普通 API-key 技术讨论放行，服务端 credential 只进入 Authorization header；该失败不可重试、不回显正文，也不形成外部副作用。响应 `model` 缺失、错型或错配则在一次已发生调用后以闭集 envelope reason 拒绝，不重试、不泄露实际值。
