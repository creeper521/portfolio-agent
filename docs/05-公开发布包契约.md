# 公开发布包契约
<!-- DOCUMENT_STATUS: CURRENT_AUTHORITY -->

> **合同版本：** schema `4.0`
> **定位：** 私有治理、人工 Approval、发布工具、数据库投影和后端严格 Loader 之间的当前公开内容合同。
> **当前快照：** 版本与数量只见 [当前实现状态](08-当前实现状态.md) 的受检区块和实际 manifest。

## 信任边界

公开候选包不是私有审核包。候选只包含已经脱敏、允许公开、可由人工复核的 canonical payload；原始日报、私有 Markdown、内部截图、凭据、审核意见和未批准 Evidence 不得进入候选或运行包。

人工 Approval 绑定 canonical payload 的精确字节、decision ledger 和 Preset contract set。发布端不得对已批准内容重排、补默认值、迁移 schema 或做语义改写。

## 七文件运行包

启用当前本地 retrieval 的完整 release 必须原子包含：

```text
<contentVersion>/
├─ manifest.json
├─ portfolio.json
├─ presentation.json
├─ rag-documents.jsonl
├─ keyword-index.json
├─ vector-index.bin
└─ checksums.json
```

职责：

- `manifest.json`：release 入口、版本、Approval、哈希、计数、兼容版本和 retrieval 描述；
- `portfolio.json`：公开事实、主体、证据关系、Case、Collection、Timeline 与 Preset；
- `presentation.json`：受控展示配置；
- `rag-documents.jsonl`：由公开 Claim 派生的 canonical 检索文档；
- `keyword-index.json`、`vector-index.bin`：发布端使用固定实现派生的索引；
- `checksums.json`：canonical 数据文件与派生索引的 SHA-256。

七个文件属于同一 release。缺失、额外文件、校验和不符、版本不一致或引用不闭合时，整个 Bundle 加载失败；不得部分启用。

## 路径与文件规则

- 文件必须直接位于 release 根目录；
- 禁止绝对路径、父目录跳转、符号链接、junction、设备文件和未声明文件；
- JSON 使用 UTF-8，unknown field 失败；
- ID、slug、code 和引用在各自作用域内唯一；
- `schemaVersion` 与 `contentVersion` 在相关文件中一致；
- manifest 的 counts 必须等于事实文件的实际集合大小；
- `minimumApplicationVersion` 不兼容时拒绝加载；
- 任何校验失败都不能退回未校验内容。

## Manifest 合同

`manifest.json` 至少包含：

- `schemaVersion`、`contentVersion`、`publishedAt`、`builtAt`；
- `minimumApplicationVersion`；
- `factsFile`、`presentationFile`、`checksumsFile`；
- `approvalId`、`approvalDigest`、`candidatePayloadHash`；
- `ledgerHash`、`presetContractSetHash`；
- Project、Case、Claim、Evidence、ClaimEvidenceLink、TimelineEvent 与 QuestionPreset 的 counts；
- retrieval 开启时的模型、维度、相似度、规范化、策略、文件格式与 artifact hash。

manifest 只能引用合同允许的文件名。Approval、ledger、Preset set 或 retrieval 描述与实际字节不符时拒绝发布和加载。

## Portfolio 事实文件

`portfolio.json` 顶层为 closed schema：

- `schemaVersion`
- `contentVersion`
- `owner`
- `projects`
- `cases`
- `collections`
- `claims`
- `evidence`
- `claimEvidenceLinks`
- `timelineEvents`
- `questionPresets`

### Project

Project 是长期主线或具有独立交付边界的公开作品。它必须明确状态、贡献类型、技术、验证、结果、Claim/Evidence/Timeline 引用，以及职业方向和展示层级。

Project 状态与贡献类型不能由展示文案扩大。featured Case 必须真实存在，并且满足 Project/Case 关系约束。

### Case

Case 是独立案例主体，不是 Project 的匿名附属段落。它必须包含稳定 ID、code、slug、类型、标题、问题、行动、决策、验证、结果、限制、状态、贡献类型和公开引用。

`projectId` 可以为空；存在时必须引用真实 Project。Case 的 Claim 必须以 `subjectType=CASE` 指向该 Case，不能借相关 Project 的 Claim 隐式补证。QuestionPreset、Collection、Evidence 与 Timeline 引用必须存在且不能跨主体伪造支持关系。

### Claim、Evidence 与关联

Claim 明确主体类型、主体 ID、类别、陈述、详情、完成状态、贡献类型、验证基础、验证状态、重要性、主题和受众优先级。

Evidence 只公开元数据摘要。运行包中的 Evidence 必须为 `APPROVED`，且 `rawContentPublic=false`；原始证据正文保持私有。

Claim 与 Evidence 的支持只能通过 `ClaimEvidenceLink` 建立。关联必须引用现有实体，明确 support type、scope 和 review status；不能从相似文本自动推断支持。

### TimelineEvent 与 Collection

TimelineEvent 的 Project、Case、Claim、Evidence 引用必须闭合。Collection 只组织 Case 展示，不改变 Case 的事实、状态、贡献或证据边界。

### QuestionPreset

QuestionPreset 是发布内容合同的一部分，不是前端硬编码文案。它包含：

- 稳定 `id`、公开 `text` 与 aliases；
- audiences、topics、placements 和 display order；
- Project/Case 主体引用；
- preferred Claim categories；
- `deterministicEntry`；
- `contractSubjectId`；
- required/supporting Claim IDs；
- evidence requirement；
- `contractStatus`。

带 `presetId` 的前端入口必须提交 PRESET 命令并携带对应 revision/contract 信息。只有满足当前发布与状态规则的 Preset 才能成为可操作入口；DRAFT 不得被前端当作 ACTIVE 行为。缺少 presetId 的 Case 建议才可降为公开 FREE_TEXT。

## Presentation 合同

`presentation.json` 使用与事实文件一致的 schema/content version，并只包含：

- audiences；
- homeSections；
- metrics；
- explorePortals；
- footer。

Presentation 可以排序、分组和选择已存在的公开实体，但不能创造 Project、Case、Claim、Evidence 或成绩事实。对未知 ID、重复位置和不完整展示配置应失败关闭。

## RAG 与索引合同

`rag-documents.jsonl` 每行是 closed 文档，至少绑定 chunkId、contentVersion、公开 Claim、Project/Case slug、topics、有效期、contentHash 和公开 text。

- text 只能从已批准公开 Claim 派生；
- Project 与 Case 引用必须与 Claim 主体一致；
- contentHash 必须匹配规范化后的公开文本；
- 查询、向量、分数和运行时候选不属于发布包；
- 候选不能提供可直接信任的 keyword/vector index；
- 发布端必须使用固定本地模型复现已批准 RAG 字节，再派生并校验索引；
- 模型 descriptor、artifact hash、维度、归一化和策略变化需要新 release。

## Checksums 与原子性

`checksums.json` 记录事实、展示、RAG 和派生索引的 SHA-256。Loader 在解析业务内容前验证文件集合与校验和。

发布按临时目录写入完整 release，验证后原子移动到版本目录；active 指针只能指向完整、可验证的不可变版本。相同 contentVersion 不得映射到不同 payload 或 ledger。

## 数据库投影

PostgreSQL 公开库只保存不可变 release 投影和一个显式 active 指针。导入不等于激活；激活不改变 canonical bytes。数据库读取结果必须维持与 Bundle Loader 相同的主体、Evidence、Preset 和引用边界。

治理库保存私有源与审核过程，使用不同数据库、账号和权限，不得由公网应用读取。

## 隐私与发布阻断

以下任一情况阻断候选、Approval、发布或加载：

- 出现私有路径、凭据、原始日报、未审核截图或原始 Evidence；
- Evidence 未批准或声明原文可公开；
- Claim 状态、贡献或结果超出审核来源；
- Project/Case/Preset/Timeline 引用悬空或主体不一致；
- canonical payload、Approval、ledger、Preset set、checksums 或索引描述不匹配；
- 使用外部 Embedding Provider 或未经校验的本地模型；
- 尝试覆盖既有 contentVersion 或部分更新 active release。

实际操作步骤见 [公开内容发布运行手册](06-公开内容发布运行手册.md)。
