## 权威顺序

1. 用户当前明确决定与 [AGENTS.md](../AGENTS.md) 的产品、安全边界；
2. 当前已批准设计及其可追溯实施计划：[稳定化设计](superpowers/specs/2026-08-19-agent-stabilization-and-repository-governance-design.md)、[稳定化计划](superpowers/plans/2026-08-19-agent-stabilization-and-repository-governance.md)、[通用回答语言与深度设计](superpowers/specs/2026-08-20-general-answer-language-and-depth-prompt-design.md)、[对应实施计划](superpowers/plans/2026-08-20-general-answer-language-and-depth-prompt.md)、[项目讨论上下文设计](superpowers/specs/2026-08-20-project-discussion-context-design.md)、[已完成的项目讨论实施计划](superpowers/plans/2026-08-20-project-discussion-context.md)、[公开作品集 API 单资源收敛设计](superpowers/specs/2026-08-21-portfolio-public-api-convergence-design.md) 与 [对应实施计划](superpowers/plans/2026-08-21-portfolio-public-api-convergence.md)；
3. 生产代码、配置、自动化测试与可复现运行证据；
4. 当前权威文档；
5. 历史文档和评审备忘录。

文档与代码冲突时，不得为了保留旧文案扭曲实现；应先取得证据，再修正文档或代码。没有新鲜验收证据时，不得声明生产已完成。

## 历史与非权威文档

除上文明确列出的 `APPROVED` 设计与 `ACTIVE` 实施计划外，`docs/01-03`、`docs/07`、`docs/11-14`、其他 specs/plans、`docs/reports` 与 `docs/handoffs` 只保存当时的背景、决策、实施路径和证据。它们必须带正式状态标记，但不会因为旧内容与当前实现不同而被改写成“现在的事实”。

状态标记语义：`CURRENT_AUTHORITY` 是持续维护的当前规则或运行文档；`APPROVED` 是已经批准的当前设计；`ACTIVE` 是正在执行的当前计划；`HISTORICAL`、`SUPERSEDED` 与 `NON_AUTHORITATIVE` 均不能证明当前行为。

[项目演进日志](11-项目演进日志.md) 是日期正序的摘要导航，不是当前功能清单；详细过程以 Git 历史和对应设计、计划、报告为准。
