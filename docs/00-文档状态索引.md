## 2. 文档权威顺序

发生冲突时，按以下顺序判断：

1. `AGENTS.md` 的产品和安全边界；
2. `docs/04-项目代码约束.md` 的当前工程约束；
3. 已确认的 A/B/C Agent 设计与对应公开发布契约；其中 A/B、C1、C2 与 C3 中仅 Model Provider Registry 已实现；其余 C3 能力待真实准入；
4. 已实施的 V0、前端重构和公开内容联调设计；
5. `docs/01-03` 的长期产品/技术路线；
6. 已完成或已取代的历史实施计划与审核记录。

历史计划中的勾选表示该计划步骤已经执行，不代表后来没有发现新的缺口。标记为“已取代”的未勾选清单不属于当前待办。

`docs/12-工程质量与未来优化评审备忘录.md` 不参与上述权威排序。它只保存阶段性评审观察、证据和可能方向，不构成需求、实施计划、版本承诺或验收基线；发生冲突时必须回到权威文档与当前可复现证据重新判断。
