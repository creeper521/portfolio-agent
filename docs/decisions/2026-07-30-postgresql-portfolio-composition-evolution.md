# PostgreSQL 资产包组合的演进决策

日期：2026-07-30
状态：后端 V1 已实现，数据库能力默认关闭，等待环境门禁和同口径基准实测。

## 决策

检索只负责生成候选，不能直接成为最终资产包。候选进入一个独立、确定性、
受约束的组合阶段，V1 使用小候选集穷举；`SelectionStrategy` 保留 TopK、
贪心和 LLM rerank 的演进位置，但 LLM 不拥有最终发布或充分性判定权。

公开运行数据使用“规范化 PostgreSQL 投影 + 不可变兼容快照”。规范化表支持
结构过滤、FTS、pgvector 和关系校验；兼容快照保证现有文件 Bundle 语义可逐项
比对和回退。迁移完整度只比较公开语义、数量、关系和 canonical hash，
不接触私有治理数据，只有完全一致才能得到 `1.0000`。

公开运行库与私有治理库物理分离。公开 API 只读 active release；
治理库只接受操作者显式指定目录的手动扫描、预览、导入和重试。
不增加自动文件 watcher，避免未审内容因本地文件变化而自动进入数据库或发布链路。

## 评测约束

R0–R4 必须使用相同 release、embedding model、fixture split 和 TopK 口径。
评测输入只记录稳定公开 ID、能力标签和公开 Evidence 有效性，不记录访客原文、
本地路径、向量、凭据或治理 ID。缺失或失败的路线保持 `UNAVAILABLE`，
不得补零、平均或据此宣称提升。安全指标使用绝对计数，不能被相关性均值掩盖。

## 后续演进

只有 V1 穷举在候选规模或延迟门禁上出现可复现问题时，才评估贪心或近似算法；
只有确定性策略无法稳定区分候选且有离线标注集时，才评估 LLM rerank。
任何演进都必须保留确定性约束校验、公开 Evidence 门禁、跨 release 阻断和人工发布批准。
