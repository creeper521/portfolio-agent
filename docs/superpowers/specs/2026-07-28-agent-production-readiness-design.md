# Agent 生产可用性设计

> **状态：** 已确认，待实施  
> **日期：** 2026-07-28  
> **范围：** 单次 JSON 回答的超时、取消、幂等、限流、降级、输出校验、状态展示与密钥安全  
> **明确不包含：** 流式回答、访客隐私许可弹窗、数据库、分布式限流、跨实例幂等

## 1. 目标

在不引入 SSE、数据库或固定云网关的前提下，把现有 `/api/v2/answers`
加固为适合 V1 生产候选的单次 JSON 回答链路：

1. 请求具有明确的前端、后端和 Provider 时间预算；
2. 访客可以取消等待，迟到响应不会污染页面会话；
3. 重复提交和网络重试不会重复调用 Provider；
4. 服务端按匿名来源执行基本限流和并发保护；
5. Provider 失败时优先返回可解释的确定性降级结果；
6. 空回答、长回答、非法结构和无效引用不能进入最终响应；
7. UI 清楚区分确定性、模型、检索、降级和拒答状态；
8. API Key 只存在于服务端运行环境，不进入前端、响应、日志或制品。

本轮继续使用稳定的单次 JSON 响应。流式回答只有在 V1 生产链路稳定后再单独设计。

## 2. 已确认决策

- 不增加访客隐私提示、许可弹窗或 consent 请求字段。
- 限流按来源 IP 的短期哈希执行，不记录原始 IP。
- 每个 IP 哈希每分钟最多 10 个请求，同时最多执行 2 个请求。
- Provider 超时 8 秒，后端整请求预算 12 秒，前端等待预算 15 秒。
- 前端与后端共同实现重复提交保护。
- Provider 失败时，如果确定性回答可用，HTTP 仍返回 `200`，并显式标记降级。
- 不自动重试 Provider，不跨 Provider 故障转移。
- 所有状态继续复用现有正交领域枚举，不创建含义重叠的新枚举。

## 3. 总体架构

采用分层生产加固：

1. **HTTP 请求边界：** 提取匿名来源、限流、并发保护、幂等协调和统一错误响应；
2. **回答应用边界：** 执行 12 秒预算，调用现有 `ConversationalAgentRuntime`；
3. **Provider 边界：** 保持 8 秒 HTTP 超时，校验模型 Draft，失败后回到现有确定性 fallback；
4. **响应边界：** 校验最终响应结构、回答长度、blocks 与引用；
5. **前端请求边界：** 生成 token、禁止重复提交、主动取消、15 秒超时和迟到响应隔离；
6. **展示边界：** 把既有正交状态映射为用户可理解的标签和提示。

限流、幂等和来源哈希均为单进程内存实现，适用于当前单 JAR、单实例 V1。
未来若改为多实例部署，必须把三者迁移到共享基础设施，不能声称本设计天然支持集群一致性。

## 4. 请求契约与幂等

### 4.1 `requestToken`

`POST /api/v2/answers` 增加必填字段：

```json
{
  "requestToken": "6b2d8895-4108-4b4d-aee0-21f6e7c4f333"
}
```

约束：

- 必须是规范 UUID；
- 每次新的用户提交生成一个新 token；
- 同一次提交的网络重试复用原 token；
- token 不作为访客身份，不跨页面持久化；
- token 不转发给 Provider。

### 4.2 幂等键

服务端幂等键为：

```text
sourceHash + ":" + requestToken
```

同一个键在 2 分钟内：

- 首个请求创建共享执行；
- 并发重复请求等待同一执行结果；
- 已完成请求直接返回缓存的成功响应或稳定错误；
- 不再次调用路由、工具、检索或 Provider。

缓存只保存最终 DTO 或稳定错误类别，不保存访客原问题以外的新副本，不写磁盘，
进程重启后清空。2 分钟后条目可被惰性或定时清理。

## 5. 匿名来源与限流

### 5.1 来源解析

默认使用实际 TCP remote address。只有部署显式开启“信任代理”并配置可信代理网段时，
才读取代理提供的客户端地址头；不能无条件信任 `X-Forwarded-For`。

来源地址先与进程内随机盐做 HMAC-SHA-256 或等价密钥哈希，再进入限流和幂等键。
原始 IP 不写日志、不进入领域对象、不持久化。进程重启时盐轮换，所有来源状态自然失效。

### 5.2 策略

每个来源哈希：

- 滚动或固定 60 秒窗口最多 10 个新 token；
- 同时最多执行 2 个新 token；
- 命中幂等缓存的重复请求不重复计入新请求额度；
- 超过速率返回 HTTP `429`；
- 超过并发也返回 HTTP `429`；
- 响应包含整数秒 `Retry-After`；
- 错误正文只包含稳定错误码、用户提示和 retry 秒数。

默认采用单进程内存实现，不引入 Bucket4j、Redis 或数据库。内部时钟通过注入接口提供，
以便测试窗口推进，不使用真实等待。

## 6. 超时与取消

### 6.1 时间预算

三个预算从内到外递增：

| 层级 | 时间 | 行为 |
|---|---:|---|
| Provider HTTP | 8 秒 | 终止 Provider 等待并进入确定性 fallback |
| 后端整请求 | 12 秒 | 停止继续组装，返回合法 fallback、boundary 或稳定超时错误 |
| 前端等待 | 15 秒 | 中止浏览器请求，恢复可提交状态并显示超时提示 |

Provider 不自动重试，不切换到另一 Provider。

### 6.2 前端取消

前端每次提交创建独立 `AbortController`：

- 提交中显示“停止等待”；
- 点击后调用 `abort()`；
- 取消属于用户动作，不显示为系统故障；
- 当前执行使用单调递增 generation ID；
- 响应只有在 generation ID 仍为当前值且 signal 未取消时才能写入会话；
- 取消或超时后，迟到响应必须被忽略。

### 6.3 后端取消

客户端断开后，服务端对未完成工作做 best-effort 取消。Java HTTP 请求必须响应线程中断或
取消信号。若底层调用无法立即停止，其结果也只能完成共享幂等执行，不能产生第二次响应、
写访客内容日志或绕过输出校验。

## 7. Provider 失败与降级

以下情况都视为模型结果不可接受：

- 8 秒超时；
- DNS、连接、TLS 或非成功 HTTP 状态；
- 空响应或空白正文；
- 非法 JSON；
- 非法枚举；
- 缺少必需字段；
- `blocks` 为空；
- block 数量、单 block 长度或总回答长度超限；
- 引用缺失、引用未知或引用超出本轮已批准公开上下文；
- Draft 验证失败；
- Provider 返回内容与当前 content version 不兼容。

处理顺序：

1. 丢弃完整模型 Draft，不做局部拼接；
2. 使用同一已批准 `AnswerPlan` 或当前公开快照生成确定性 fallback；
3. 可形成合法回答时返回 HTTP `200`：
   - `generationMode=FALLBACK`
   - `degraded=true`
   - 保留真实 `resolution`
   - 返回稳定用户提示；
4. 确定性能力也无法回答时返回 `BOUNDARY` 或 `REJECTED`；
5. 只有应用异常且无法形成任何合法领域响应时才返回 `5xx`。

用户提示固定表达为：

> 模型服务暂时不可用，当前展示基于已发布内容的确定性回答。

不得包含 Provider 响应、异常正文、URL、密钥、堆栈或部署配置。

## 8. 输出预算与引用完整性

沿用现有 Draft Validator 和 Response Mapper，在最终响应边界增加统一预算：

- title 最多 120 个 Unicode 字符；
- block 总数最多 8 个；
- 每个 block 内容不得为空；
- 单 block 最多 2,000 个 Unicode 字符；
- 所有 block 内容合计最多 8,000 个 Unicode 字符；
- `ANSWERED` 至少包含一个合法 block；
- 作品集来源 block 的 Claim/Evidence 必须存在于同一 `RuntimeAnswerContent`；
- 未经批准、跨版本或跨主体引用一律拒绝；
- 前端不负责把非法长回答截断成“看似合法”的回答。

上述上限在实施时集中到一个服务端不可变预算对象；Draft Validator 和最终响应校验
必须读取同一预算，前端只负责展示合法响应，不复制或放宽服务端数字。

## 9. 回答状态与前端展示

继续使用三组现有正交状态：

### 9.1 处理结果

- `ANSWERED`
- `BOUNDARY`
- `REJECTED`

### 9.2 生成方式

- `DETERMINISTIC`
- `MODEL`
- `FALLBACK`

### 9.3 内容来源

- `PRESET`
- `RETRIEVAL`
- `TOOL`
- 现有其他封闭来源值

用户界面映射：

| 条件 | 标签/提示 |
|---|---|
| `DETERMINISTIC` | 确定性回答 |
| `MODEL` | 模型生成 |
| `RETRIEVAL` | 检索增强 |
| `FALLBACK` 或 `degraded=true` | 已降级，并显示固定降级说明 |
| `REJECTED` | 已拒答 |
| `BOUNDARY` | 当前公开内容无法可靠回答 |
| HTTP `429` | 请求过于频繁，并显示可重试秒数 |
| 前端 15 秒超时 | 请求超时，可重新提交 |
| 用户取消 | 已停止等待，不记为失败回答 |

提交中禁用同一输入的按钮和 Enter 提交，但保留“停止等待”操作。

## 10. API Key 与日志安全

- Key 只通过服务端进程环境或部署平台 Secret 提供；
- 不在仓库目录 `.env`、前端环境变量、Vite 配置、响应、URL 或测试夹具中保存真实 Key；
- 前端构建产物不得包含 Key 名对应的真实值或 Authorization；
- Provider Authorization 只能在服务端 Adapter 内部构造；
- 异常映射必须去除 Provider 响应正文和底层网络详情；
- 不记录访客原问题、完整回答、Provider 请求/响应、原始 IP 或 request token；
- 允许记录：匿名服务端 request ID、来源哈希短前缀、耗时桶、回答状态、生成方式和稳定错误类别；
- 来源哈希短前缀只能用于短期聚合诊断，不能被描述为稳定访客身份；
- 隐私扫描覆盖 Java/TypeScript、前端 dist、最终 JAR、日志语句和错误响应测试。

## 11. 错误契约

新增或复用统一错误响应字段：

```json
{
  "code": "ANSWER_RATE_LIMITED",
  "message": "请求过于频繁，请稍后再试。",
  "retryAfterSeconds": 12,
  "requestId": "server-generated-id"
}
```

稳定错误类别至少包括：

- `ANSWER_RATE_LIMITED`
- `ANSWER_CONCURRENCY_LIMITED`
- `ANSWER_REQUEST_TIMEOUT`
- `ANSWER_REQUEST_INVALID`
- `ANSWER_INTERNAL_ERROR`

用户取消通常不会收到可消费的响应，由前端本地处理。错误响应不得包含来源地址、
来源哈希、request token、问题、Provider 名称、Provider 响应或 Key。

## 12. 测试设计

### 12.1 后端单元测试

- 第 11 个新 token 在窗口内被限流；
- 60 秒窗口推进后恢复；
- 同一来源最多 2 个并发执行；
- 不同来源互不影响；
- 原始 IP 不出现在状态和日志；
- 相同 token 的并发请求只执行一次；
- 完成后的相同 token 复用结果；
- 2 分钟后 token 可重新作为新请求处理；
- 12 秒预算触发稳定结果；
- 不可信代理头不能伪造来源。

### 12.2 Provider 与输出测试

- 超时、连接失败、空响应、非法 JSON、非法枚举、空 blocks、过长 block、过长总回答；
- 缺失引用、未知引用、跨版本引用、跨主体引用；
- 所有模型失败均不泄漏响应正文，并进入同 Plan 确定性 fallback；
- fallback 不可形成时返回 `BOUNDARY` 或 `REJECTED`；
- Key、Authorization、访客问题和 Provider payload 不进入日志或响应。

### 12.3 前端测试

- 提交期间按钮和 Enter 不会产生第二次请求；
- 网络重试复用 token，新问题生成新 token；
- 停止等待会 abort，并忽略迟到响应；
- 15 秒触发前端超时；
- `429` 显示 `Retry-After`；
- `FALLBACK` 显示固定降级说明；
- 正确展示确定性、模型、检索、降级、拒答和 boundary；
- 空/非法响应进入稳定错误 UI，不写入会话。

### 12.4 集成与发布门禁

- MockMvc 覆盖 request token、429、稳定错误正文和无敏感字段；
- packaged JAR 覆盖确定性回答、Provider 故障降级、重复 token 和限流；
- 浏览器 E2E 覆盖重复点击、取消、超时、降级和恢复提交；
- 前端 dist、JAR 解包和仓库风险制品隐私扫描必须通过；
- 普通门禁不得调用真实 Provider；
- `-RequireLiveProvider` 仍是生产候选的独立显式证据。

## 13. 配置与默认值

配置必须具有安全默认值：

- `PORTFOLIO_MODEL_TIMEOUT=8s`
- 后端整请求预算 `12s`
- 前端超时 `15000ms`
- 每来源每分钟 `10`
- 每来源并发 `2`
- 幂等结果保留 `2m`
- 可信代理模式默认关闭

配置解析失败时应用应启动失败或回到更保守的固定值，不能静默放宽限流或超时。
生产日志只输出配置是否启用和非敏感数值，不输出盐、Key 或代理地址明细。

## 14. 发布与回滚

发布前必须通过：

1. 后端、前端和浏览器测试；
2. 限流、幂等、超时和降级故障注入；
3. 隐私扫描；
4. packaged JAR 单次 JSON E2E；
5. 生产候选环境的显式 Provider 验收。

回滚顺序：

1. 关闭对话模型开关，保留确定性回答；
2. 必要时关闭对话 Agent v2，保留公开内容与 v1；
3. 回滚应用制品；
4. 不回滚已批准 ContentBundle，除非内容本身存在独立问题。

## 15. 完成标准

- 10 次/分钟和 2 并发限制具有确定性测试；
- 重复 token 不会重复调用 Provider；
- 8/12/15 秒预算分别生效；
- 主动取消和迟到响应隔离通过浏览器测试；
- Provider 的空、长、非法和引用缺失输出全部被拒绝；
- 降级回答具有 `FALLBACK + degraded=true` 和明确提示；
- UI 可区分确定性、模型、检索、降级、拒答和 boundary；
- API Key、Authorization、原始 IP、访客问题及 Provider 原始内容不进入前端、日志或响应；
- 普通 CI 保持无外部 Provider 调用；
- 单次 JSON 链路通过完整发布门禁；
- 文档明确流式回答和访客许可不在本轮范围。
