## 2. 组件规范

视觉 token 全部取自 `frontend/src/app/styles/tokens.css`，不引入新颜色。演示值参照原型；落地时以现有 workspace 组件的实际 class 组织为准。

### 2.1 选择器触发钮（ModelSelectTrigger）

```text
┌─────────────────────────────┐
│ ● GLM-4.7-Flash        ▾ │   胶囊：圆角 999px，边框 --rule，
└─────────────────────────────┘   底 --paper-hi，字 11px --mono，
                                  ● = 6px 圆点 --red，▾ = --faint
```

- 内容 = 当前生效模型显示名 + 展示当前是否默认（默认时右侧不带徽标，浮层内体现）；
- `disabled`（Pending 锁定）时 `opacity .55` + `cursor: not-allowed`，**同时**由 2.3 的文字说明原因，不靠颜色单独表达；
- hover 边框转 `--red`；焦点可达（键盘 Tab 打开浮层，Esc 关闭）。

### 2.2 目录浮层（ModelCatalogPopover）

```text
╔══════════════════════════════════╗
║ GLM-4.7-Flash        [目录默认] ║   宽 252px，向上弹出（composer 顶部），
║ glm-4-7-flash · 稳定通用        ║   底 --paper-hi，边框 --agent-hairline，
║──────────────────────────────────║   圆角 --radius-md，投影 0 18px 44px
║ Qwen3.7-Flash                    ║   条目：名称（13px --sans 600）+
║ qwen-3-7-flash · 语义理解        ║   [目录默认] 徽标（9px --mono，红描边）
╚══════════════════════════════════╝   + modelRef 与一句话说明（10px --mono --faint）
```

- 数据**只来自** `/api/portfolio` 的 `agentAvailability` 模型目录投影（字段名等 A7 冻结）；前端不静态复制目录、不显示 endpoint/key 等内部信息；
- 当前选中条目底色 `--red 10%` 混合；点击即选中并关闭浮层；
- Pending 锁定期间浮层不可打开；
- 条目不可用（目录刷新后标记 unavailable）时：条目保留但降透明度 + 明确"暂不可用"文字，不可选中。

### 2.3 Pending 锁定态

- 触发钮禁用 + 发送区出现行内说明（10.5px `--mono` `--muted`）：**「回答生成中 · 本轮结束后可切换模型」**；
- 锁定范围：选择器、浮层、发送键（沿用现有 pending 规则）；会话轨不受影响（可切换浏览其他会话，各会话偏好独立）。

### 2.4 切换通知（inline notice）

选中与当前不同的模型后，在对话流插入一条轻通知卡（`--paper-hi` 底、`--agent-hairline` 边框、圆角 `--radius-sm`）：

- 主行（13px --sans）：**「已切换至 {模型名} · 下一轮回答将由它生成」**
- 副行（10.5px --mono --faint）：**「选择仅在本页会话内记忆，刷新后使用目录默认」**
- 通知为纯前端展示卡，不产生 Turn、不进入 conversationWindow（与 busy 终局同类的"非可信轮次"）。

### 2.5 回答模型标识（model tag）

- 每条 AGENT 回答消息头部右侧（`who` 行）显示 10px `--mono` 大写模型名（如 `GLM-4.7-FLASH`）；
- 数据来自该 Turn 公开响应的 `modelExecution` 投影（等 A7 冻结），**不**由前端按"当前选择"推断——回答标识必须反映该轮实际执行的模型；
- 确定性 Capability（`participation=NONE`）显示 `DETERMINISTIC` 或不显示，以 A7 投影字段为准，前端不自造第三种语义。

### 2.6 失败双动作卡（模型不可用类终局）

仅当失败类别为模型暂不可用（A7 五个 unavailable 终局之一，具体码等冻结）时，失败视图提供双动作：

```text
┌────────────────────────────────────────────────┐
│ 模型暂时不可用（eyebrow，--red）                  │
│ {模型名} 暂时无法完成这次回答                      │
│ 本轮请求已安全结束。你可以用同一请求重试，           │
│ 或换一个模型重新提问。                             │
│                                                │
│ [重试本次请求]   [换 {另一模型名} 重新提问]         │
│ 重试本次请求 = 同一请求标识重放，可能直接找回        │
│   已完成的结果                                    │
│ 换模型重新提问 = 发送一条新请求（新标识），          │
│   由另一模型重新生成回答                           │
└────────────────────────────────────────────────┘
```

- 主动作（实底 `--red`）= 重试本次请求：**同 requestId** 重放，复用现有 A2-22 提交快照（含原 ModelSelection）；
- 次动作（描边）= 换模型重新提问：**新 requestId、新 TurnSubmissionSnapshot、携带新选模型**；点击后先出现 2.4 切换通知（副行改为「新请求标识 {requestId 前缀} · 不复用原请求的任何结果」），再进入 pending；
- 两条 faint 说明行是语义区分的关键，**不可省略**；其余失败类别（网络、限流、合同）沿用现有 `turnFailureProjection` 单动作文案，不出现换模型入口。

### 2.7 首页徽标（LightAnswerPanel）

- 回答面板底部一行（10.5px `--mono` `--faint`）：**「由 {默认模型名} · 目录默认 生成」** + 弱化后缀「首页不提供切换，进入 Agent 页后可选」；
- 首页 handoff 进入 Agent 页时按目录默认初始化会话偏好（handoff 种子不携带模型字段）。

### 2.8 空目录态（显式 NONE）

承上级设计决策 9（目录为空时使用显式 `NONE`，确定性 Capability 仍可用）：

- 触发钮降级为**只读状态块**：`确定性回答 · 未配置模型`（无浮层、无圆点高亮）；
- 发送区说明行常显：**「当前部署未配置可选模型，仅提供基于公开资料的确定性回答」**；
- 自由文本语义路由在无模型时本就不可用（现有 availability 语义），沿用现有禁用文案，不重复造新入口。

### 2.9 失效选择态（stale selection）

页面存续期间目录投影刷新（如 portfolio 重取）导致已选模型不在目录或标记不可用时：

- 会话偏好**回退到目录默认**，并插入一条通知：「{原模型名} 当前不可用，已回到目录默认 {默认名}」；
- 不静默回退——回退必须可见；
- 若该会话存在未完成的 pending Turn，则**不**中途回退（单 Turn 单模型不变量优先），终局后再生效回退通知。

## 3. 交互状态机

```text
                 ┌─────────────┐
        ┌───────►│ idle(A)选中态 │◄────────────────┐
        │        └──────┬──────┘                  │
   关闭浮层/选中同项      │ 打开浮层                  │终局(含CLARIFICATION)
        │        ┌──────▼──────┐   选中其他项       │
        │        │ open 浮层展开 │──────┐           │
        │        └─────────────┘      │           │
        │                        ┌────▼────────┐  │
        │                        │ switched 通知 │──┘（下一轮按新选择）
        │                        └─────────────┘
  提交 Turn（任意来源）                          目录刷新致失效
        │                                          │
┌───────▼────────┐   终局到达     ┌──────────────┐ │
│ pending 锁定    │─────────────►│ 回到 idle     │◄┘（pending 中延迟到终局）
│ (选择器禁用+文字)│              │ 或 stale 回退  │
└───────┬────────┘              └──────────────┘
        │ 模型不可用类失败
┌───────▼────────┐  同请求重试──► pending（原快照）
│ failure 双动作   │
│                │  换模型重问──► switched通知(新请求) ──► pending（新快照）
└────────────────┘
空目录：idle 直接呈现 NONE 只读态，浮层不存在
```

规则要点：

1. **会话独立性**：偏好挂在 `AgentSession`（页面内存），切换会话各自展示各自选择；新建会话从目录默认开始；
2. **单 Turn 单模型**：pending 期间选择器锁定且目录失效回退延后；快照中的 ModelSelection 即该轮执行权威；
3. **通知不进窗口**：2.4/2.9 通知卡是纯展示，conversationWindow 与 latestRecommendationReference 一类推导均忽略它（与 A2-69 busy 终局同列的非可信轮次规则）；
4. **键盘可达**：触发钮 Tab 可达、浮层内方向键选择、Esc 关闭、Enter 确认。

## 5. 与既有机制的对接（实施清单）

### 5.1 TurnSubmissionSnapshot 扩展（A2-22 模式延续）

- 快照新增"当轮 ModelSelection"（字段名等 A7；快照仍是页面内存、原样复用的唯一权威）；
- **同 requestId 重试**：原样复用快照（含原模型选择）——重试不换模型；
- **换模型重问**：构造**新**快照、新 requestId、携带新选择；绝不复用旧快照改字段（保持 A2-22"冻结完整提交身份"的不变量）；
- 首页 `failedSubmission`（A2-72/73 修复引入）同样纳入 ModelSelection。

### 5.2 agentTurnApi 请求体

- 请求类型新增闭合 `ModelSelection` 载荷（`MODEL(modelRef + selectionVersion) | NONE`），字段名、枚举值、序列化形状**以 A7 fixtures 为准**，冻结前不写任何请求代码；
- 请求指纹由后端定义是否纳入选择；前端不自行二次指纹。

### 5.3 Slice B：`turnWindowSummary()` 退位

- B3 检查点后 conversationWindow 改为消费后端 `conversationProjection`（最近 6 组完整 USER/ASSISTANT 对、失败/无 PublicTurn 输入不进窗口）；
- 前端删除 `turnWindowSummary()` 旧权威（含 2.4/2.9 通知卡不进窗口的本地规则届时由投影天然保证）；
- 迁移期间**不**保留双摘要开关（版本级回退）。

### 5.4 会话与状态落点

| 文件 | 变更 |
|---|---|
| `components/ModelSelector.vue`（新） | 触发钮 + 浮层 + 锁定/只读态，props 驱动，无内部目录知识 |
| `components/AgentWorkspace.vue` | 集成选择器、切换/stale 通知、失败双动作分支、快照扩展 |
| `model/sessionTypes.ts` / `useLocalSessions.ts` | `AgentSession` 增加内存模型偏好字段（默认 undefined = 目录默认） |
| `api/agentTurnApi.ts` | ModelSelection 载荷（A7 后）；`turnFailureProjection.ts` 增模型不可用类别的双动作映射 |
| `features/audience/*` | LightAnswerPanel 徽标；首页 handoff 不带模型字段 |
| `model/publicAgentTurn.ts` + mapper | modelExecution 投影解析（additive，A7 fixtures 驱动） |

### 5.5 目录来源与刷新

- 目录只从 `/api/portfolio` 投影读取（页面已有原子快照通道）；不新增请求轮询，随既有 portfolio 获取节奏；
- 刷新后 diff 目录：新增模型进浮层、移除/不可用触发 2.9 stale 规则。

## 6. 隐私与安全边界

1. 模型选择**只**存在于页面内存（会话对象）与 Turn 请求体；不写 localStorage/sessionStorage、不进 URL/历史、不进前端诊断事件；
2. 浮层只显示后端投影允许公开的信息（显示名、modelRef、默认/可用性徽标）；endpoint、key、Provider 内部配置一律不出现；
3. 回答标识以该轮 `modelExecution` 投影为准，前端不做"应该是谁"的推断；
4. 切换通知/stale 通知不携带访客问题文本（模板字符串仅含模型名与固定文案）。

## 8. 验收标准（前端责任区）

1. 组件单测：触发钮/浮层/锁定/NONE/stale/不可用条目全状态断言（含键盘操作）；
2. Workspace 集成测试：切换后下一轮请求携带新选择且当轮标识为新模型；pending 期间切换被拒并有文字原因；模型不可用失败出现双动作；「重试」复用同 requestId 与原快照（含原选择），「换模型重问」产生新 requestId 且旧快照不被改写；stale 回退通知出现且 pending 中延后；通知卡不进 conversationWindow；
3. 首页测试：默认模型徽标、handoff 种子不含模型字段；
4. `vitest` 全量、`vue-tsc`、`vite build`、Vue warning 为零；
5. packaged-JAR E2E（随 Slice A 门）：桌面+移动至少覆盖「默认模型问答 → 会话内切换 → 下一轮跨模型续问」与「模型不可用 → 换模型重问」两条链路；
6. 任何依赖真实 Provider 的最终门保持 pending，不提前宣称。

## 9. 明确不做

- 不持久化偏好（刷新/新会话回默认是特性不是缺陷）；
- 不做模型对比、双模型并行回答、自动 failover（上级设计已禁止）；
- 不在失败以外场景提供"换模型重问"入口（避免把新请求语义混入正常重试路径）；
- 不改动 workspace 视觉系统的其他部分；不引入新颜色/字体 token；
- 不在前端复制或推断目录内容与可用性。
