# Agent 前端体验闭环交接设计
<!-- DOCUMENT_STATUS: NON_AUTHORITATIVE -->

> **日期：** 2026-08-17
> **状态：** 已批准设计，交由前端 Agent 实施
> **范围：** 前端展示与交互规格；本文不授权后端或本文作者修改前端代码

## 1. 用户目标

Agent 页面首先服务面试官或访客快速理解公开项目。答案是主内容，证据用于建立信任，执行状态用于解释异常；内部编排信息不是默认阅读对象。

## 2. 设计原则

- 答案优先，证据按需，执行异常优先于成功过程；
- 不向访客暴露内部 ID、枚举、协议名或兼容状态；
- 同一事实只显示一次，同一状态只有一个主表达；
- 数量未满足、证据不足和任务失败必须明确，不以“执行完成”掩盖；
- 保留工程档案的纸张、墨色、灰褐和暗红视觉语言；
- 不使用绿色状态色，不恢复通用 SaaS 面板风格。

## 3. 后端新契约依赖

前端 Agent 应等待或兼容以下字段：

- 推荐：`requestedSize`、`actualSize`、`candidateScope`、`selectedPortfolioIds`；
- 未满足信息：`unsatisfiedConstraints`、`reasonCodes`；
- 任务状态：`ANSWERED`、`PARTIALLY_ANSWERED`、`NOT_SUPPORTED`；
- 证据：`publicSourceCatalog` 与每个 Block/Recommendation Item 的 `sourceReferences`；
- 执行：语义去重后的唯一任务列表；
- 正式预设：顶层 Blocks 与 Completed Task Blocks 在兼容期内容一致。

前端不得自行推断缺失项目、补造证据、扩大主体范围或把 PARTIAL 改成 COMPLETED。

## 4. 页面信息层级

### 4.1 默认桌面布局

- 中央答案区为唯一主滚动区；
- 会话列表保留，但允许折叠，不能持续抢占答案宽度；
- 证据工作台默认收起或显示简洁入口；用户点击引用时再打开并聚焦；
- 输入框固定在答案区底部，但不得覆盖最后一段内容；
- 不要求本轮新增路由。

### 4.2 成功回答

默认只显示：

1. 用户问题；
2. 回答正文；
3. 一行公开来源摘要，例如“依据 2 组已审核公开证据”；
4. 与当前任务直接相关的后续操作。

成功回答默认隐藏四阶段执行快照和内部回答构成。用户主动展开“查看回答依据”时，才显示任务与来源明细。

### 4.3 澄清状态

输入 `1` 等噪声时：

- 显示简短澄清文案；
- 提供三类安全入口：了解项目、比较项目、推荐项目；
- 不显示执行完成、已验证证据或 Answer Focused；
- 不把页面默认项目写进文案。

### 4.4 部分推荐

当 `actualSize < requestedSize`：

- 标题使用“找到 1/3 个符合条件的项目”这类明确表达；
- 状态使用“部分完成”，不得使用“执行完成”；
- 展示服务端公开原因，例如“其余公开项目的证据完整度暂不足”；
- 保留已找到的项目卡片；
- 提供一个主要恢复操作，例如“放宽条件重新推荐”；
- 不重复显示多个泛化状态徽章。

### 4.5 失败或不支持

- 显示用户可以理解的原因和下一步；
- 技术 reasonCode 仅用于映射，不直接显示；
- 不显示空的任务进度或伪成功阶段；
- Evidence 面板保持关闭，除非响应包含可公开引用。

## 5. 执行信息

- 成功时执行信息默认折叠；
- PARTIAL、FAILED、BLOCKED 时自动显示简短摘要；
- 多任务必须显示任务名称，不能只重复四个阶段；
- 同一任务只出现一次；
- 不展示协议枚举 `ANSWERED · EVIDENCE_COMPOSITION`；
- 可将其翻译为一条人类可读状态，例如“已根据公开证据整理回答”。

## 6. 证据交互

- 引用显示公开编号和标题，例如 `E-01 · SQL 审计工具交付证据集`；
- 禁止显示 `[sql-audit-delivery-set]` 等内部 Evidence ID；
- 点击章节引用时，证据工作台打开并只聚焦该章节引用；
- 点击回答级来源摘要时，展示该回答全部引用；
- 提供“查看全部 63 条公开证据”作为二级入口，不与当前引用混在同一默认列表；
- 关闭证据工作台后焦点返回触发按钮；
- Evidence、引用和来源三类标签必须说明差异，或合并为用户可以理解的单一入口。

## 7. 推荐交互

- 卡片数量必须与 `actualSize` 一致；
- 标题区显示请求数量和实际数量；
- 推荐理由来自服务端，不在前端重新排序或生成；
- “换掉这个”“为什么推荐这个”仅在存在可信 Context Handle 时展示；
- 通用推荐后的建议问题不得被默认 SQL 项目污染；
- 后续建议优先围绕当前结果集合，而不是页面默认项目。

## 8. 会话列表

- 纯数字、过短输入不能直接成为永久会话标题；
- 澄清会话可显示“待补充问题”；
- 正常问题生成可扫描的短标题，保留完整问题作为辅助信息；
- 会话选择不得改变新问题的主体范围，除非恢复的是可信会话 Context；
- 明确区分“展示中的项目”与“对话已确认主体”。

## 9. 视觉和无障碍

- 成功、通过和可信状态使用墨色、灰褐、暗红细节、图形和文字，不使用绿色；
- 正文字号保持 14–16px，长文本控制舒适行长；
- 状态不只依赖颜色；
- 所有展开、关闭、证据引用和推荐操作支持键盘；
- 抽屉打开后管理焦点，关闭后恢复焦点；
- 200% 缩放不产生横向页面溢出；
- 桌面三栏和窄屏抽屉都只保留一个主要阅读焦点；
- 尊重 reduced-motion，不依赖动画传达状态变化。

## 10. 兼容策略

- 优先消费去重后的 Semantic Turn 任务结果和 Public Source Reference；
- 正式预设兼容期可消费顶层 Blocks，但必须验证其与 Completed Task Blocks 属于同一内容版本；
- 新数量字段缺失时，不得根据卡片数量宣称“全部满足”；使用中性文案；
- sourceReferences 存在时禁止回退展示内部 Evidence ID；
- 后端完成统一投影后，另立任务移除旧 Evidence ID 回退，不在本次交接中擅自删除协议兼容代码。

## 11. 前端验收场景

### 场景 A：噪声输入

输入 `1`：显示澄清，无答案卡、无执行完成、无证据聚焦。

### 场景 B：两项目推荐

显示两张项目卡；默认项目不影响结果；标题和 aria-label 均表达“2 项”。

### 场景 C：三项目部分完成

若后端返回 `actualSize=1`、`requestedSize=3`：显示“找到 1/3 个”，状态为部分完成并展示原因。

### 场景 D：SQL 正式预设

只显示一组任务状态；回答章节不重复；引用显示公开证据编号和标题。

### 场景 E：证据聚焦

点击章节引用后打开证据工作台，只展示当前章节证据；关闭后焦点回到引用按钮。

### 场景 F：视觉规范

页面没有绿色状态色、内部 ID、重复成功标签和无意义英文枚举。

## 12. 前端 Agent 交付要求

前端 Agent 应：

1. 先为上述六个场景补充组件和端到端失败测试；
2. 只修改前端，不自行改变后端契约语义；
3. 保留现有工程档案视觉语言；
4. 用后端真实响应或合同 fixture 验证 PARTIAL、澄清和 Evidence Focus；
5. 交付前运行单元测试、构建、关键端到端测试和无障碍检查；
6. 提供修改前后截图，重点覆盖默认成功、澄清、部分推荐和证据聚焦。
