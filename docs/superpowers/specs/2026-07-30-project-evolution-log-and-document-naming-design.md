# 项目演进日志与项目文档中文命名设计
<!-- DOCUMENT_STATUS: NON_AUTHORITATIVE -->

日期：2026-07-30  
状态：已实施

## 1. 目标

为 Agent 项目建立一份可持续维护的项目演进记录，用于按日期和开发阶段回顾功能、重要修复、产品决策与技术选型的变化。

同时将 `docs` 根目录中的 `05–09` 文档改为中文文件名，使项目级文档入口更易识别；现有目录分类保持不变。

## 2. 目录结构

实施后的项目文档入口为：

```text

├─ 01-项目背景.md
```

`decisions`、`handoffs`、`reports`、`superpowers/specs` 和 `superpowers/plans` 均保留原位置。

实施期间本地 PostgreSQL / pgvector 运行手册已由并行工作正式进入 `master`，因此项目演进日志从原定的 `10` 顺延为 `11`，不覆盖或移动现有运行手册。该运行手册随后统一命名为 `10-本地PostgreSQL与pgvector运行手册.md`。

## 4. 文档职责

- `00-文档状态索引.md`：项目文档的权威状态入口。
- `04-项目代码约束.md`：所有开发任务必须遵守的工程约束。
- `05-公开发布包契约.md`：内容模型、Bundle、发布加载和兼容规则的权威契约。
- `06-公开内容发布运行手册.md`：治理、审批、发布和回滚的操作规范。
- `07-模块化单体后端审核记录.md`：用于理解架构演进的历史审核，不作为新的实施授权。
- `08-当前实现状态.md`：当前功能、默认开关、能力边界和部署状态总账。
- `09-作品集资产库状态.md`：内容资产、公开范围、治理批次和发布状态总账。
- `11-项目演进日志.md`：按时间记录功能与选型如何演进，不替代当前状态总账。

## 5. 项目演进日志

文件路径：

```text
docs/11-项目演进日志.md
```

文档标题：

```markdown
# Agent 项目演进日志
```

### 5.1 记录范围

日志记录：

- 每个独立功能的形成和完成；
- 对外行为或使用体验有影响的重要缺陷修复；
- 产品边界、领域模型或信息架构的变化；
- 技术选型的提出、选择、受限启用、替换或退出；
- 默认开关、部署状态和能力准入边界的变化；
- 对后续项目方向有影响的治理、发布和安全机制。

日志不记录：

- 具体代码实现步骤；
- 测试命令和验证过程；
- Git 提交哈希或提交范围；
- 纯格式调整；
- 只补充测试但不改变能力的提交；
- 不改变行为的内部机械重构。

### 5.2 时间与粒度

- 按日期从早到晚排列，便于回顾完整项目历程。
- 每个日期下面按实际开发阶段拆分。
- 每个功能、重要修复或选型演进分别描述，不把同一天的所有工作压缩成一个笼统总结。
- 设计日期与实现日期分开记录。
- 只有设计或计划证据时，状态不得写成“已实现”。

### 5.3 状态词

- **提出**：形成想法或待确认方向。
- **选定**：已经完成选择，但尚未实现。
- **已实现**：已经进入当前项目能力。
- **受限启用**：已经实现，但受审批、配置或环境限制。
- **默认关闭**：已经实现，但默认运行路径不启用。
- **已取代**：曾经采用，后来被新方案替换。
- **未部署**：本地能力已经完成，尚未进入生产环境。

### 5.4 条目结构

每个阶段至少包含：

```markdown
### 阶段名称

- 功能或决策发生了什么变化。
- 该阶段与前序方案的关系。
- 当前状态：已实现／默认关闭／已取代／未部署。
- 相关设计：[文档名称](相对路径)
```

没有对应设计文档时可以省略“相关设计”，不得创建虚假引用。

## 6. 历史回填范围

首版日志回填 `2026-07-14` 至 `2026-07-30` 的项目历程。

信息来源的优先级为：

1. `AGENTS.md` 的产品与安全边界；
2. `docs/00-文档状态索引.md`；
3. `docs/08-当前实现状态.md`；
4. 已确认设计规格及实施计划；
5. Git 主分支提交时间线；
6. 决策、交接和评测报告。

回填应覆盖但不限于：

- V0 产品边界、后端基线与模块化单体；
- 前端重建和公开内容 API 联调；
- 运行时可信、内容治理、C1、C2a、C2b 与受限 C3；
- Agent 工作台视觉与交互演进；
- CaseStudy、公开资产、检索评测和发布闭环；
- 对话式 Agent v2 与结构化输出契约；
- 生产可用性、Case 信息架构和可观测性；
- Schema 4.0、PostgreSQL 双库、Markdown 增量导入、组合推荐与 R0–R4 评测。

## 7. AGENTS.md 维护规则

在根目录 `AGENTS.md` 增加以下约束：

- 每完成一个独立功能、重要缺陷修复、产品边界变化或技术选型变更，必须在任务结束前更新 `docs/11-项目演进日志.md`。
- 日志记录“实现或决策了什么、与前序方案的关系、当前状态”，不记录代码步骤、测试过程和提交信息。
- 纯格式调整、单纯补测以及不改变行为的内部机械重构无需单独记录。
- 功能、默认开关或产品边界变化时，同时更新 `docs/08-当前实现状态.md`。
- 公开资产、治理批次或发布状态变化时，同时更新 `docs/09-作品集资产库状态.md`。
- 涉及发布包或内容发布流程时，读取并遵守 `docs/05-公开发布包契约.md` 与 `docs/06-公开内容发布运行手册.md`。
