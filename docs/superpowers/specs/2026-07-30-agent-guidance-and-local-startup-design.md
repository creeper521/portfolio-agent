# Agent 动态引导、会话标题与安全本地启动设计

日期：2026-07-30
状态：已与用户逐段确认，待书面复核
适用项目：`D:\code\agent`

## 1. 背景与问题

当前 Agent 已实现模型回答、确定性降级和动态建议问题，但三个运行行为破坏了实际对话体验：

1. 会话标题直接取首个问题的前 24 个字符。长问题进入顶部标题后会被容器直接裁切，既不形成稳定摘要，也没有明确的省略行为。
2. `ConversationalAgentRuntime` 在模型未准入、Provider 失败或模型结果校验失败时，会提前返回 `DeterministicConversationFallback`。该 fallback 固定返回空 `suggestedQuestions`，`DynamicQuestionService` 只在模型回答成功后执行。因此降级状态下用户只能自行猜测可执行问题，接近无法继续对话。
3. 项目根目录 `.env` 虽然配置了模型开关和密钥，但 Spring Boot、Maven 和 `java -jar` 默认不会读取该文件。后端进程仍使用 `application.yml` 中的 `false` 默认值，导致 `providerAccess.isAllowed()` 拒绝模型调用并稳定进入降级路径。

本设计把三项问题作为同一个“对话可持续性”改进处理：本地启动必须明确证明 AI 是否可用；无论 AI 是否可用，每个完成回合都必须给出三个可执行入口；会话标题在模型可用时获得语义摘要，在模型不可用时也必须稳定、可访问。

## 2. 目标与非目标

### 2.1 目标

- 提供一条命令启动本地前端与后端，并明确区分“配置完整”“Provider 可用”和“正在降级”。
- 每个已完成的 Agent 回合返回恰好三个经过可回答性校验的建议问题。
- 建议问题随项目对话进度从项目内深入逐步迁移到跨项目探索。
- 用户显式要求查看其他项目时，三个建议全部指向其他项目。
- 模型回答成功后使用语义摘要作为会话标题；模型不可用时使用确定性单行省略标题。
- 保持访客内容不持久化、不写日志，保持公开内容和外部 Provider 的既有安全边界。

### 2.2 非目标

- 不引入持久会话、数据库会话记录或跨设备同步。
- 不增加动态 Provider、自动 Provider 故障转移、重试或模型热发现。
- 不让运行时读取私有 Obsidian 内容或未审批候选资料。
- 不让 Spring Boot 隐式加载项目根目录 `.env`。
- 不单独调用模型生成标题；标题复用本轮已验证回答中的语义标题。

## 3. 方案选择

### 3.1 引导阶段判定

考虑过三种方式：

1. 只按轮数切换：实现简单，但重复提问也会错误推进阶段。
2. 完全交给模型判断：语义自然，但模型降级时失效。
3. 规则与语义结合：使用稳定主题维度作为权威状态，模型可用时辅助识别，模型不可用时仍能确定性运行。

采用方案 3。

### 3.2 会话标题

考虑过单行省略、最多两行完整显示和语义摘要三种方向。采用“语义摘要优先、确定性单行省略兜底”：

- 模型成功：使用已验证回答标题作为会话语义摘要。
- 模型未启用、失败或输出被拒绝：保留由首个问题生成的确定性标题，并使用真正的单行省略表现。

## 4. 总体架构

本次变化保持现有模块化单体，不增加新的远程服务。

```text
scripts/start-local.ps1
  -> 解析仓库外 Secret
  -> 配置与工具链预检
  -> 启动 Spring Boot + Vite
  -> Provider 固定探针
  -> 输出 MODEL / DEGRADED 状态

POST /api/v2/answers
  -> Subject Guard
  -> Provider Access
  -> Intent Route
  -> 模型回答或确定性回答
  -> Conversation Progress Classifier
  -> Suggestion Candidate Provider
  -> 统一可回答性与去重校验
  -> 恰好 3 个 suggestedQuestions

前端 AgentWorkspace
  -> 渲染回答
  -> 渲染 3 个引导问题
  -> 首次模型成功时升级会话标题
```

回答生成与问题建议不再存在“模型成功才生成建议”的控制流分叉。任何可返回给用户的完成结果都必须进入统一建议问题阶段。

## 5. 安全的一键本地启动

### 5.1 命令与 Secret 文件

新增入口：

```powershell
scripts/start-local.ps1 -SecretsFile C:\安全目录\portfolio-agent.local.env
```

`-SecretsFile` 必须是仓库外的绝对路径。脚本不自动发现或读取根目录 `.env`，也不从当前目录向上搜索 Secret。

Secret 文件采用受限 `KEY=VALUE` 格式：

- 允许空行和以 `#` 开头的注释；
- 拒绝重复字段、无等号行和空字段名；
- 只接受白名单中的模型与本地启动变量；
- 不执行变量替换、命令、PowerShell 表达式或脚本；
- 不输出任何 Secret 值。

### 5.2 必要配置

对话式 Agent 启用前必须同时满足：

- `PORTFOLIO_MODEL_ENABLED=true`
- `PORTFOLIO_MODEL_DATA_POLICY_APPROVED=true`
- `PORTFOLIO_CONVERSATIONAL_AGENT_ENABLED=true`
- `PORTFOLIO_VISITOR_MODEL_DATA_POLICY_APPROVED=true`
- `PORTFOLIO_MODEL_PROVIDER` 是 Registry 中允许的 Provider
- 所选 Provider 对应的 API Key 非空

脚本还检查 Java 21、Maven、Node、前端依赖和端口 8080/5173。检查失败时不创建子进程，并按字段列出缺失或非法项。

> **补充说明（2026-08-04）：** 前端默认端口已由 5174 统一为 5173，直接 `npm run dev` 与启动器都强制 `--strictPort`；直接前端启动的日志落盘入口见 [Direct Vite Local Logging Design](2026-08-04-direct-vite-local-logging-design.md)。

### 5.3 进程生命周期

预检通过后，启动脚本：

1. 只把允许的变量注入本次后端子进程，不污染用户级或机器级环境变量。
2. 启动 Spring Boot `local` Profile。
3. 等待公开健康入口和内容 API 就绪。
4. 启动 Vite 开发服务器。
5. 运行一次固定、无隐私的 Provider 探针。
6. 持续托管两个子进程；任一进程异常退出时清理另一进程。
7. 用户按 `Ctrl+C` 时关闭本次创建的两个子进程。

脚本不得停止启动前已经存在的 Java、Node 或其他进程。端口已占用时直接报告占用，不猜测或终止占用者。

### 5.4 Provider 探针

探针使用固定的已审批公开内容问题，不包含访客输入、历史会话、密钥或内部环境信息。探针必须检查：

- HTTP 请求成功；
- 响应契约有效；
- `generationMode=MODEL`；
- 没有 `degraded=true`；
- 回答通过既有引用和结构校验。

只有探针通过时，终端才显示“AI 已连接”。环境变量完整但探针失败时，服务可以继续以降级模式运行，终端显示标准化失败类别：

- 认证失败；
- Provider 超时或不可达；
- Provider 响应格式错误；
- 模型输出验证失败；
- Registry 或策略不兼容。

输出不得包含密钥、完整 Provider 响应、访客问题、请求正文或内部堆栈。

## 6. 对话阶段与三个引导问题

### 6.1 主题维度

项目或案例对话使用以下稳定主题维度：

- `BACKGROUND`：背景与目标；
- `RESPONSIBILITY`：个人职责与贡献边界；
- `SOLUTION`：方案和实现；
- `TRADEOFF`：取舍与替代方案；
- `FAILURE`：故障、困难与排查；
- `VERIFICATION`：验证方式与证据；
- `OUTCOME`：结果、状态与局限。

覆盖状态只存在当前页面会话及请求内临时上下文，不进入浏览器持久存储、服务端持久化或日志。

### 6.2 阶段状态

阶段由已覆盖维度和用户显式意图决定：

| 阶段 | 典型状态 | 项目内问题 | 其他项目问题 |
|---|---|---:|---:|
| `OPENING` | 已覆盖 0–2 个维度 | 3 | 0 |
| `DEEPENING` | 已覆盖 3–4 个维度 | 2 | 1 |
| `WRAP_UP` | 已覆盖 5–7 个维度 | 1 | 2 |
| `EXPLORE_OTHERS` | 用户明确要求推荐或了解其他项目 | 0 | 3 |

显式探索意图优先级最高。主题覆盖阈值必须是集中定义、可测试的确定性规则，不能散落在 Prompt 或前端组件中。

模型可用时可以辅助把自然语言映射到主题维度，但不能直接决定阶段；最终阶段必须由确定性分类器根据已接受的维度标识计算。显式探索意图包括“推荐其他项目”“还有什么项目”“换个项目看看”等封闭意图分类；它只改变下一轮建议配比，不修改已覆盖维度。

### 6.3 候选来源

统一建议服务接收当前主体、阶段、近期问题、已覆盖主题和当前公开快照。

- 模型可用且本轮模型回答有效：可使用模型提出的候选问题。
- 模型不可用、调用失败或候选无效：使用当前公开 `QuestionPreset`、项目和案例内容确定性构建候选。
- 两类候选进入完全相同的校验、排序和补齐流程。

确定性补齐顺序为：

1. 当前主体尚未覆盖的 QuestionPreset；
2. 当前项目下的相关案例；
3. 与当前主题相关的其他项目；
4. 全局公开项目中的可回答问题。

跨项目候选不得重新指向当前项目。明确的 `EXPLORE_OTHERS` 阶段跳过项目内候选。

### 6.4 统一校验

每个建议问题必须：

- 指向当前公开快照中存在的 Project 或 Case；
- 通过既有 Grounding/`canAnswer` 校验；
- 不需要私有、实时或外部信息；
- 不与当前问题或最近六个用户问题语义重复；
- 不与本轮其他候选重复；
- 长度和文本结构符合 API 契约；
- 携带稳定的 `projectSlug` 或 `caseSlug` 目标上下文。

语义重复首先按稳定主体、主题维度和规范化文本判断；模型相似度只能作为额外过滤，不能成为降级路径的依赖。跨项目候选优先覆盖不同项目；若公开内容不足，再允许同一其他项目贡献多个不同主题问题。

过滤后不足三个时继续按确定性补齐顺序取候选。公开 Bundle 的激活约束增加“至少三个全局可回答问题”，从数据源头保证安全补齐可成立。

最终服务返回恰好三个 `ConversationSuggestedQuestion`。不能因为模型、Provider 或模型建议失败而返回空数组。

### 6.5 特殊结果

- `ANSWERED`、`BOUNDARY`、`REJECTED` 和确定性 fallback 都必须附带三个安全建议问题。
- 敏感或越权请求被拒绝后，建议问题用于把用户带回公开作品集范围。
- 实时问题无法回答时，建议问题不得伪装成实时内容。
- 网络断开、限流和 HTTP 失败不属于“完成回答”。前端保留重试入口，并从已加载公开内容中展示三个安全入口；这些入口不伪装成服务端本轮建议。

## 7. 会话标题

### 7.1 确定性初始标题

首个用户问题提交后立即生成初始标题：

- 去除首尾空白并规范连续空白；
- 保留原始语义，不使用模型；
- 存储完整规范化字符串，视觉层只做单行省略；
- 顶部标题和左侧历史栏使用同一字段；
- 完整标题通过可访问名称、聚焦/悬停提示和首条用户消息保持可见。

### 7.2 语义标题升级

第一轮有效模型回答返回后，如果回答标题满足以下条件，则将会话标题升级为语义标题：

- 以 Unicode code point 计为 4–24 个字符；
- 不是“能力边界”“无法处理”“回答”等通用文案；
- 本轮 `generationMode=MODEL` 且模型回答通过完整验证；
- 会话尚未自动升级；
- 用户没有手动重命名。

标题直接复用回答标题，不产生额外模型调用。会话最多自动升级一次；后续对话、跨项目建议或模型标题变化不再自动改名。

模型未启用、失败、超时或输出被拒绝时，保留确定性初始标题。用户手动重命名后永久锁定本会话的自动标题更新。

## 8. 前端行为

- 每条已完成 Agent 回答下固定展示三个建议按钮。
- 点击建议按钮立即发起下一轮，并携带其 Project/Case 目标上下文。
- 三个按钮必须支持键盘访问、清晰焦点和窄屏换行。
- 后端契约异常地返回少于三个建议时，前端从当前已加载的公开问题池补齐，并发送不包含访客内容的诊断事件。
- 前端补齐属于故障隔离措施，不能替代后端“恰好三个”的主契约。
- 标题容器设置正确的 `min-width: 0` 与单行省略规则，不能依靠父容器 `overflow: hidden` 直接裁切文本。
- 屏幕阅读器读取完整会话标题，而不是视觉截短后的内容。

## 9. 错误处理与观测

启动脚本和运行时使用封闭错误类别，不记录敏感正文：

- `LOCAL_CONFIG_INVALID`
- `LOCAL_TOOLCHAIN_MISSING`
- `LOCAL_PORT_OCCUPIED`
- `PROVIDER_AUTH_FAILED`
- `PROVIDER_TIMEOUT`
- `PROVIDER_UNAVAILABLE`
- `PROVIDER_RESPONSE_INVALID`
- `PROVIDER_DRAFT_REJECTED`
- `SUGGESTION_CONTRACT_RECOVERED`

诊断事件只记录类别、阶段、生成模式、候选数量桶和补齐来源，不记录问题文本、建议问题文本、Prompt、完整响应、密钥、URL、Header 或堆栈。

## 10. 测试与验收

### 10.1 启动脚本

- 仓库外合法 Secret 能正确注入本次子进程。
- 仓库内 Secret、重复字段、未知敏感字段和缺失必要项会被拒绝。
- DeepSeek/GLM 只检查各自对应密钥。
- 端口占用不会终止已有进程。
- 任一子进程失败和 `Ctrl+C` 都只清理本次创建的进程。
- 探针只有在真实 `MODEL` 响应时报告“AI 已连接”。
- 所有失败输出都不包含密钥。

### 10.2 后端

- 覆盖维度驱动 `OPENING → DEEPENING → WRAP_UP`。
- 显式探索意图强制进入 `EXPLORE_OTHERS`。
- 四个阶段分别满足 `3+0`、`2+1`、`1+2`、`0+3`。
- Provider 未准入、Provider 失败、超时、空响应和 Draft 校验失败时仍返回三个建议问题。
- `ANSWERED`、`BOUNDARY`、`REJECTED` 均返回三个建议问题。
- 当前问题、近期问题、当前项目跨项目候选和不可回答候选均被过滤。
- Bundle 少于三个全局可回答问题时拒绝激活。
- 建议问题不会扩大公开事实或 Evidence 范围。

### 10.3 前端

- 每个完成回答渲染三个可点击按钮。
- 点击跨项目/案例建议时上下文正确切换。
- 请求失败时同时提供重试和三个本地安全入口。
- 首次模型成功后标题升级一次；fallback 不升级；手动重命名阻止升级。
- 长标题在顶部和历史栏显示省略号，完整文本仍可通过键盘和辅助技术访问。
- 在既有桌面、平板和手机验收视口中无横向溢出、无遮挡和直接裁切。

### 10.4 完整验证

实现完成后运行项目权威门禁，包括前端测试与构建、后端测试、架构与隐私检查、packaged-JAR E2E。真实 Provider 探针属于显式本地/生产候选验证，普通 CI 不得误触外部 Provider。

## 12. 实施边界

预计修改范围：

- 本地启动与探针脚本；
- 对话运行时的统一建议阶段；
- 对话进度分类器与建议候选选择；
- fallback 结果构建；
- Bundle 激活校验；
- 前端会话标题升级和建议问题故障补齐；
- 对应测试、README、当前状态与演进日志。

实施不得顺带引入持久会话、数据库对话状态、动态 Provider、自动重试、SSE 或新的外部数据源。
