# Agent 2.0 动态缺陷与开发账本重构设计

<!-- DOCUMENT_STATUS: APPROVED -->

> 日期：2026-08-26  
> 状态：用户已批准  
> 目标文件：`docs/15-Agent 2.0真实交互问题清单与修复边界.md`

## 1. 目标

把 `docs/15` 从历史实施流水重构为只维护当前开放问题的唯一工作账本。删除已关闭正文、历史测试计数、旧制品哈希和已被当前实现取代的阶段结论；历史通过 Git 与 `docs/11-项目演进日志.md` 查询。

## 2. 文档结构

重写后的文档只保留：

1. 当前结论与完成边界；
2. 维护、编号和删除规则；
3. 不得被局部修复破坏的稳定不变量；
4. 按 `NOW / NEXT / LATER` 排序的开放工作总览；
5. 按工作流组织的详细开放项；
6. 固定依赖顺序与全局 Exit Gates。

每个开放项必须包含稳定 ID、严重度、状态、现状证据、目标、修复边界、依赖和可执行 Exit Gate。事实、推断和未来方案不得混写。

## 3. 编号与保留规则

- 仍开放且已被代码、真实运行或当前权威设计证明的问题保留原 `A2-NN`；
- 已关闭条目从总览、正文、专属测试缺口和 Exit Gate 中全部删除；
- 新发现的生产缺陷从 `A2-118` 继续单调编号，不复用旧 ID；
- 纯架构维护使用 `ARCH-NN`，验证治理使用 `GATE-NN`，文档治理使用 `DOC-NN`，避免把非产品缺陷伪装为真实交互 Bug；
- 不保留已关闭 ID 索引。

## 4. 纳入范围

账本必须覆盖当前仍开放的：

- Release 假绿与场景证据缺口；
- Qwen Comparison 的 Goal Draft v1 阻断及 Goal v2 决策；
- Recommendation 满数量但约束未满足的投影与展示；
- 冷恢复 Token、跨 JVM 与 Discussion/多轮恢复；
- General/Comparison 合同容量、pair 身份、句数、字符和 Provider 语义一致性；
- Qwen/GLM 独立真实矩阵、Browser 正文、调用计数与生产稳定性；
- Gateway、Binding、Readiness、Lifecycle、Workspace、Store 等已证实影响扩展或正确性的架构债；
- docs/08、docs/11、docs/00、SECURITY 和机器状态的同步治理。

## 5. 删除范围

以下内容不再进入 `docs/15`：

- A2-01 等已关闭问题的历史正文；
- 每批 Maven/Vitest 数量、旧 JAR SHA-256、旧 Provider 版本与阶段执行日志；
- 已被当前 Qwen v6、GLM v4 和当前模型目录替代的历史结论；
- 与开放问题无直接关系的实现叙事；
- 可以直接从 Git、测试源码或 `docs/11` 恢复的过程证据。

## 6. 完成与回退

本次只改变治理文档，不改变生产运行时。完成需满足：文档只含开放事项；所有本轮确认的待办可追踪；ID 无重复；无隐私正文；文档、架构和隐私检查通过。若新结构遗漏开放责任，可用 Git 恢复旧文档后重新整理，不建立双账本。
