## 1. 目标

把 `docs/15` 从历史实施流水重构为只维护当前开放问题的唯一工作账本。删除已关闭正文、历史测试计数、旧制品哈希和已被当前实现取代的阶段结论；历史通过 Git 与 `docs/11-项目演进日志.md` 查询。

## 2. 文档结构

重写后的文档只保留：

1. 当前结论与完成边界；
2. 维护、编号和删除规则；
3. 不得被局部修复破坏的稳定不变量；
4. 按 `NOW / NEXT / LATER` 排序的开放工作总览；
5. 按工作流组织的详细开放项；
6. 固定依赖顺序与全局 Exit Gates。

每个开放项必须包含稳定 ID、严重度、执行序、状态、现状证据、目标、修复边界、依赖、专属测试/验证缺口和可执行 Exit Gate。事实、推断和未来方案不得混写。

严重度与执行序正交：`P0/P1/P2/P3` 只表达问题影响，`NOW/NEXT/LATER` 是唯一执行顺序。执行时先遵守上游依赖，再按同一执行序内的严重度排序；不得因为某项严重度较低就绕过它作为下游工作的前置条件。

最终条目总数必须由完成删除/保留/合并/重分类裁决后的实际 ID 集合计算，不手写沿用评审阶段的估算数字。

## 3. 编号与保留规则

- 仍开放且已被代码、真实运行或当前权威设计证明的生产行为问题保留原 `A2-NN`；legacy A2 中属于验证、架构或文档治理的事项不保号，严格迁移到对应命名空间；
- 已关闭条目从总览、正文、专属测试缺口和 Exit Gate 中全部删除；
- `A2-118`—`A2-120` 已分配；后续新生产缺陷从 `A2-121` 继续单调编号，不复用旧 ID；
- 纯架构维护使用 `ARCH-NN`，验证治理使用 `GATE-NN`，文档治理使用 `DOC-NN`，避免把非产品缺陷伪装为真实交互 Bug；
- 本轮严格迁移后的水位为 `A2-120`、`ARCH-22`、`GATE-23`、`DOC-09`；即使条目以后关闭并删除，水位仍只增不减；
- `ARCH`、`GATE`、`DOC` 独立维护显式水位线、单调递增且永不复用；`GATE-01` 已关闭，不回到开放正文，也不得复用；
- 不保留已关闭 ID 索引。

水位线只记录“编号曾被使用到哪里”，不记录历史问题标题、状态或正文，因此不构成已关闭事项档案。新增条目前必须先提升对应水位线，再分配下一个 ID。

评审阶段使用过的 `R/G/REC/RES/GOAL/GEN/V/A/D` 等前缀只允许作为工作流分组标签，不是账本 ID，不建立水位线，也不得替换既有 A2 引用。正式账本只允许 `A2`、`ARCH`、`GATE`、`DOC` 四个命名空间。

“仍开放”必须有当前证据：代码路径、当前自动化失败/缺口、真实运行结果或当前批准设计的未完成 Exit Gate 至少一项，并在条目中给出文件、测试、脚本或权威文档位置。只有历史计划曾经提出、但当前代码与运行证据无法证明仍存在的内容不得保留。

## 8. 删除裁决与审计

重写前生成一次性删除/保留裁决表，至少包含原 ID、裁决、当前依据和新位置：

- `DELETE`：生产修复与风险对应门已有当前证据，或条目明确标记已关闭；正文从 `docs/15` 删除，关闭依据类别写入 `docs/11`；
- `KEEP`：仍有当前生产缺陷、验收缺口或批准设计 Exit Gate 未满足；保留原 A2 ID，并改写为精简开放项；
- `MERGE`：多个条目是同一根因和同一 Exit Gate；保留最早仍开放的 ID，其他 ID 按已使用编号进入水位但不保留历史索引，合并关系写入本次治理记录；
- `RECLASSIFY`：不是用户可见生产缺陷，但确属待完成架构、验证或文档治理；迁移到 `ARCH/GATE/DOC` 新 ID，原 A2 ID 进入删除裁决记录。

本轮 36 项严格执行 `RECLASSIFY`，集合和新位置以 §3.1 为准。未发现“同一根因且同一 Exit Gate”的候选项，因此本轮 `MERGE=0`；原条目的严重度、执行序、状态、证据、目标、边界和 Exit Gate 原样迁移，只允许同步跨 ID 依赖和替换即将历史化的治理文档定位。

每个候选项必须重新从当前 HEAD 核对完整调用顺序，而不是沿用评审摘要中的因果结论；后置兜底、相邻层测试或字段已经存在，均不能替代对原失败路径的顺序证明。无法闭合机制但已有可信风险路径时只能标为“待验证”，并把最小复现列为第一条验证缺口。

裁决表是本次提交审计材料，可以体现在工作区临时检查结果和 `docs/11` 的精简治理记录中；不得把完整旧正文或测试流水重新复制进新账本。
