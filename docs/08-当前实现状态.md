## 当前结论

项目已经形成公开作品集浏览和单一 Agent Turn 运行链。Agent 的 Command、Goal、Plan、Execution、Projection、State 与无版本 HTTP 资源均由 `turn` 链负责；旧运行入口、`answer` 与 `selection` 生产包均已物理删除。失败恢复与项目讨论补完正在执行，[架构状态](agent-architecture-status.json) 为 `IN_PROGRESS`。

配置化用户可选模型目录、A2-117 Provider Draft 编译层和低信息输入隔离已进入唯一生产链。Goal 先校验 `goal.provider-draft.v2`（v1 仅保留历史样本回归注册），再由确定性 Compiler 编译为 `goal.proposal.v5`；goal 级 `inputText` 已从 Provider 义务中移除，canonical `inputAnchor` 由服务端从受信 currentInput 前缀机械派生，主体级锚点仍执行已审核别名与唯一精确子串校验。

2026-08-28 已实现但尚未提升的 Qwen v7 General Explanation 候选把 CONCISE、STANDARD、DETAILED 作为不可拆分能力：`general.provider-draft.v4 -> general-provider-draft-compiler.v4 -> general.draft.v3`，canonical 恒为服务端派生的 DEFINITION 与 MECHANISM 两条 statement；自然句边界分别为 1+1、每 role 1..3、每 role 4..6。Provider wire 兼容 `string|string[]`，可选 caveats 缺失或整组无效可降级，unknown root 只计数；关键解释、身份、权限、secret、资源和 canonical 语义仍失败关闭。候选 JAR 只配置硬编码为 `selectable:false` 的 v7，因此自身不会把 Qwen 暴露到公开目录；现网与公开合同 fixture 继续保留 Qwen v6，候选不能据此部署，旧选择也不会静默迁移。General Comparison 在独立认证前于 Goal 后、Provider 前固定返回 `OUT_OF_SCOPE`，General Provider 调用为 0。

Qwen v4 General 仅对连接/无响应超时、502/503/504 及受限 429 允许最多一次同模型 transport retry；两次 attempt 共享原 absolute deadline、冻结相同请求语义，并显式计量重复计费风险。任何 2xx 后 JSON、envelope、Provider Schema、Compiler、canonical 或 semantic 错误均不重试；Goal、GLM、跨模型 fallback 与运行时 repair 均未放宽。唯一 Transport seam 在 HTTP 与 Provider 调用诊断前扫描最终 payload 文本值，高置信 secret 赋值、standalone API key 与 PEM 私钥标记以闭集 SAFETY 失败关闭，普通 API-key 技术讨论不误拒；服务端 credential 只进入 Authorization header。2xx 响应根级 `model` 必须存在、为字符串并精确等于冻结 binding 的模型身份，错配只产生闭集诊断而不泄露实际值。诊断实验室只接受固定合成 corpus，raw artifact 位于 repo 外且精确 24 小时过期；正式证据只接受由实际 endpoint 派生的 `REAL_PROVIDER`，测试环回不能形成认证。当前仅完成离线候选和认证工具，真实 300 条 Qwen 采样、生产提升、GATE-19 与两家独立 LIVE 矩阵仍为 `NOT_RUN/IN_PROGRESS`。

## 已实现能力

### 公开作品集

- Vue 前端提供概览、Project、Case、时间线、证据中心与 Agent 工作台；
- Project/Case 公开主体显式且互斥，未知主体失败关闭；
- 公开内容由随包 Bundle 提供，也可从已激活的 PostgreSQL 公开投影读取；
- 公开读取面收敛为唯一无版本 `GET /api/portfolio`，一次返回同一 `contentVersion` 的完整 Project、Case、Claim、Evidence、Timeline、Preset 与 Agent 可用性投影；
- Case 到 Agent 的交接不把问题写入 URL 或浏览器持久存储；
- 公开内容、错误响应和 Agent 响应遵守脱敏与禁止缓存边界。

### Agent Turn

- 唯一生命周期执行 claim、Goal 解析、Plan 编译、能力执行、公开投影和一次性 settlement；
- 支持作品集解释、比较、推荐、通用知识、跨域综合、安全社交输入与 typed Clarification；
- 相同 `requestId` 支持幂等终局重放；确定性 Portfolio Turn 精确重放并保留可用的 opaque ContextHandle，Provider 派生的 General/Conversational 正文只在首次响应返回，同 requestId 重试得到固定 `CAPABILITY_UNAVAILABLE/REPLAY_BODY_NOT_RETAINED`（“该回答未被保留，请重新提问。”）且不再次调用 Provider；主动取消与 deadline 采用一次性终局，迟到结果不得提交；
- 推荐未指定数量时使用安全默认值，合法有界数量直接执行，不因未点名候选而强制澄清；
- Clarification 保存最小 typed blocked Goal，不持久化原问题；Challenge 一次消费，同字段不得重复澄清；
- Clarification V5 在执行前按 requestId 短期预约，只有 terminal settlement 事务才能消费；失败、取消或预约过期不产生半消费终局；
- Goal Interpretation 与 General Knowledge 的固定 system prompt 随 JAR 发布并在启动时无条件校验；Qwen v7 候选对 General Explanation 三档分别强制 2、2..6、8..12 个自然句，canonical role/aspects 仅由服务端派生为 DEFINITION/MECHANISM，并检查受信 topic、主要语言与关键正文非空；深度信息量和可读性由分 depth 盲审证明，不以 Provider 自报 coverage 假装运行时语义证明；
- Portfolio Fact 与 cross-domain 使用同一闭合 depth：depth 会改变 overview 检索 profile、候选上限、必需 coverage 和公开区块/detail；澄清恢复保留该 typed depth，缺必需公开证据时只形成 PARTIAL。Portfolio comparison 只接受 ARCHITECTURE、IMPLEMENTATION、OUTCOME、RISKS、VERIFICATION 五种后端枚举维度；
- Goal 的 requestedOutputs 不再保存为独立下游权威；它必须与 typed parameters 精确一致，并在 Plan 编译时从 typed intent 重新派生。Reviewed Preset 的 outputs 同样由实际 facet 派生；
- Portfolio Recommendation 只接受当前公开目录派生的 `CAREER_TRACK_*` / `CAPABILITY_*` 约束；requestedSize 与约束进入 Bundle/PostgreSQL 候选元数据、语义排序和 coverage，未满足项公开为 `unsatisfiedConstraints`。Comparison 按闭合 dimension 对齐主体 Claim 与公开来源；
- 模型准入只保留三层独立权威：`model-runtime` 总开关、每个 Provider 的 `enabled + credential + data-policy-approved`、以及 Goal/General 各自的 Operation mode/schema/max-output/timeout；旧 global Provider、visitor access 与 Operation `provider-ref` 门已删除，Operation schema 仍与唯一生产 Codec 在启动期精确校验；
- `ConfiguredModelCatalog` 从启动配置冻结 GLM `glm-4-7-flash -> glm-4.7-flash` 与 Qwen `qwen-3-7-flash -> qwen3.7-flash` 的安全目录；`catalogVersion` 同时纳入默认选择、公开条目字段与服务端 descriptor fingerprint，后者覆盖全部 Operation binding fingerprint，因此合同或编译绑定变化即使不改变公开 JSON shape 也会使旧目录快照失效；`/api/portfolio` 只公开目录版本、默认选择和 modelRef/selectionVersion/displayName，不公开 endpoint、Profile、descriptor fingerprint 或凭据；
- 每个 Turn 根级必须显式携带 `MODEL(modelRef + selectionVersion)` 或 `NONE`，选择进入请求指纹；新 Claim 在回放判定后解析并冻结一个 `ModelExecutionSnapshot`，Goal 与 General 显式复用同一模型；仅 Qwen v4 General 的批准 transport 闭集可在共享 deadline 内重试一次，不能跨模型重发；
- `PublicAgentTurn.modelExecution` 与终局原子结算并回放，闭合记录 `NONE/GOAL_INTERPRETATION_ONLY/ANSWER_GENERATION/GOAL_AND_ANSWER/ATTEMPTED_UNAVAILABLE`；目录 stale/unavailable 以及 Provider 临时不可用、限流、非法响应分别形成五种 HTTP 200 settled `CAPABILITY_UNAVAILABLE`；
- STANDARD 自由文本只接受 AI 提出的 closed SemanticRoute，后端验证 Goal、公开主体、数量、约束与候选范围；原推荐/数量/比较/约束/指代 NLP fallback 已物理删除，模型关闭时自由文本明确不可用；
- 页面 `subjectHint` 经当前公开目录解析为 trusted `defaultSubject`；STANDARD 单主体 Portfolio/跨域省略表达由后端绑定 `SURFACE_HINT`，显式公开主体仍可覆盖默认。AudienceRole 进入所有 task，General Provider 接收闭合角色，Portfolio 仅在相同证据范围内调整 facet 优先级；
- 短期状态保存上一成功 Portfolio Turn 的无正文 typed semantic state，并与终局原子结算；PostgreSQL 只保存独立 AES-GCM envelope。Goal 只有在 Provider 返回属于该状态的显式 `recentReference.goalId/sectionId` 后才允许后端注入 `RECENT_TURN`，模型漏 subject 不会自动继承旧主题；
- Discussion 的 `NEEDS_CLARIFICATION` 不再退化为解释不可用：active pointer 生成五种服务端闭合 facet 的短期加密 challenge，expired pointer 只生成重进选择；澄清结算使用 pointer generation guard，选择后由后端构造锁定项目的 deterministic Goal，不重新解释原访客文本；
- 非快速路径 Conversational 的 Provider 正文在进入公开 Turn 前受运行时校验：最多 160 字、以中文为主体、拒绝完整英文句、控制字符和较长访客输入的连续复述；固定快速问候仍由服务端文案处理；
- Recommendation item 携带后端生成的 ENTER_RESULT action；ProjectDiscussionContext、Conversation active pointer 与短期 typed state 是当前项目焦点及短期续问状态的唯一权威，CONTINUE 已闭合为 ENTER_RESULT、ROUTE_IN_CONTEXT、EXIT_CONTEXT、REENTER_SUBJECT；
- 当前项目焦点支持卡片进入、受限候选切换、显式退出、过期重建与刷新恢复；页面只恢复 typed focus，不恢复聊天消息，handle 与 resultItemId 不进入 URL 或浏览器持久化；
- 单调 revision 投影每次 pointer 变更；成功 Turn 与 replay 返回当前权威 discussion summary，前端按 revision 单调消费，不再用热路径二次 GET 推测状态；
- 前端 pending、failure、draft 与 notice 按本地 session 隔离；同标签页并发、失败重试、同 requestId replay 与 active cancel 仍需完整 Browser 验证。

### 生产保护

- 每来源速率与并发限制、单实例 Active Turn 上限和单 Turn 任务并行上限均有独立边界；
- Turn 使用覆盖 Goal、Planning、Execution、Projection 与 Settlement 的 absolute deadline；各子操作受自身上限和剩余预算共同约束；
- `429 RATE_LIMITED` 同时返回 `Retry-After` Header 与 `retryAfterSeconds`；
- 来源地址只做进程内匿名 HMAC，不保存原始地址；
- 外部模型没有通用自动重试或跨 Provider 重发；唯一例外是 Qwen v4 General 的有界同模型 transport retry，完整响应体仍受 operation timeout、共享 absolute deadline 与 256 KiB 上限约束。
- 最终 Provider payload 在唯一 Transport seam 执行高置信 secret-like 预检；命中发生在 HTTP/Provider 事件前，投影固定 `OUTBOUND_SECRET_LIKE_REJECTED/SECRET_LIKE_CONTENT`，不保留命中文本、不可重试且不计为已发起 Provider 调用。
- Provider 2xx envelope 的 `model` 必须与冻结 binding 精确一致；缺失、错型或错配分别形成 closed reason，均计为已发生一次调用且不可重试。
- GLM/Qwen 分别使用闭合的 `ZHIPU_CHAT_COMPLETIONS` / `DASHSCOPE_CHAT_COMPLETIONS` Profile；Goal 与 General binding 使用 required single-tool 作为只读 response carrier，并按 Provider 冻结 finish-reason extractor，不执行工具。两家的 Goal binding 均冻结 `goal.provider-draft.v2 -> goal.proposal.v5`；已部署/公开合同基线的 Qwen v6 仍绑定 General v3/v2，不可选择候选 Qwen v7 精确绑定 General v4/v3/compiler v4，GLM General 保持 `general.draft.v2` identity。共享 Gateway 固定执行 Draft Schema、Compiler、canonical Schema 与 semantic validation；candidate Codec 只接受不透明的已结构验证 carrier。Transport 将鉴权、限流、5xx、非法 JSON、envelope、Draft Schema、Compiler 与 canonical Schema 错误投影为 closed diagnostics，不把 Provider 原始响应带入生产诊断。
- Goal Draft 仅允许根级 `goal`、`recentReference`、`clarification` 在 Provider tool arguments 中作为 JSON object carrier 字符串被严格解码一次；重复键、合法对象后的尾随 token、不可解析文本和非对象结果全部失败关闭，不递归解码其他字符串。未选 route 的根级 sibling 若为显式 `null` 只视同缺省，所选分支仍执行精确字段与语义校验；该兼容边界不做语义 repair、补猜、重试或 fallback。
- 未接线的 Portfolio 模型表达端口、编译器和 4 秒幽灵预算已删除；Portfolio 继续使用确定性 presentation，并受 Turn 剩余预算与数据库 3 秒上限约束。Goal/General Provider Codec 拒绝合法 JSON 后的 trailing token，Goal carrier 内层也使用 duplicate-key 与 trailing-token 严格读取器。
- Portfolio Fact 按 `AnswerSectionType` 合并同类事实与全部实际来源，不再逐 Claim 生成碎片 section；Cross-domain 关系段由 General mechanism 和闭合 Claim category 生成，并保留 General caveat 作为适用边界。该确定性表达不扩大公开证据范围。

### 短期状态

- `POSTGRESQL` 是标准本地与生产模式；`IN_MEMORY` 用于快速开发和测试；`DISABLED` 是只读浏览模式；
- Context schema 固定为 `agent_context`，由 Flyway 管理；
- Challenge 使用 5 分钟 absolute TTL；Project Discussion 默认 20 分钟；Conversation、其他 Continuation Context、Replay 与终局记录使用 30 分钟 absolute TTL，读取不续期；
- Token 与 payload 分别加密，当前密钥与 previous-key 窗口受配置约束；
- 浏览器仅在当前标签页 `sessionStorage` 保存一个 ResumeToken，不保存问题、回答或会话历史。

## 默认配置

- `local` Profile 默认使用 PostgreSQL Agent State，启动器只检查数据库 readiness；
- `prod` Profile 强制使用 PostgreSQL，配置不完整时失败关闭；
- 模型运行、每个 Provider 数据策略、每个模型 Operation、本地检索、公开数据库读取、治理导入和前端诊断按各自开关显式启用；不再存在独立 global/visitor 模型门；
- 普通本地开发不要求 Provider Secret；模型只有同时通过 model-runtime、对应 Provider 和对应 Operation 三层准入才会执行。`selectable=false` 的已批准 Provider 只可供服务端受控 canary，不进入公开目录或访客 Turn 解析。

当前预算基线为：Turn 20 秒，其中预留 2 秒 settlement；Goal Interpretation、General Knowledge 与数据库操作分别受 8 秒、10 秒和 3 秒上限约束；确定性 Portfolio 执行受 Turn 剩余预算约束；前端等待 25 秒，lease 为 35 秒。

## 尚未完成或不得宣称

- 尚未生产部署，未形成生产流量、生产数据库或线上稳定性结论；
- 批准目录当前包含 GLM-4.7-Flash 与 Qwen3.7-Flash 两个模型目标；真实 Provider Transport 仍由 Key、endpoint、modelRef 与对应 Operation 门共同准入。低信息首轮在进入 Provider 前保持 `modelExecution=NONE`。两家独立、可比较的成功矩阵尚未闭合，不能形成整体线上稳定性结论；
- A2-15 恢复路径仍未完成真实 Provider LIVE 验收；
- GLM/Qwen 的独立真实 Provider schema、质量与 P95 门，以及桌面/移动 Browser 门仍为 `IN_PROGRESS`，架构状态不得提前恢复 `COMPLETE`；

- 当前离线边界包括冻结 binding/fingerprint、Provider compiler/extractor、Transport 资源边界、closed diagnostics、批准错误闭集内最多两 attempt 和无自动 fallback；真实 Transport、Schema 与质量只由分层运行证据决定。Qwen v7 仍不可选择，A2-80/A2-86/A2-117 不能因离线边界存在而关闭；
