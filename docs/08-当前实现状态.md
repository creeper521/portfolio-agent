## 当前结论

项目已经形成公开作品集浏览和单一 Agent Turn 运行链。Agent 的 Command、Goal、Plan、Execution、Projection、State 与无版本 HTTP 资源均由 `turn` 链负责；旧运行入口、`answer` 与 `selection` 生产包均已物理删除。失败恢复与项目讨论补完正在执行，[架构状态](agent-architecture-status.json) 为 `IN_PROGRESS`。

前端交互修复已通过全量单测、类型检查、构建及 PostgreSQL packaged-JAR 桌面/移动端矩阵。真实 Provider 已获授权并完成通用回答语言/深度固定矩阵与项目讨论原始路径；A2-15 恢复路径仍未完成对应 LIVE 验收。当前仍未生产部署。

## 已实现能力

### 公开作品集

- Vue 前端提供概览、Project、Case、时间线、证据中心与 Agent 工作台；
- Project/Case 公开主体显式且互斥，未知主体失败关闭；
- 公开内容由随包 Bundle 提供，也可从已激活的 PostgreSQL 公开投影读取；
- 公开读取面收敛为唯一无版本 `GET /api/portfolio`，一次返回同一 `contentVersion` 的完整 Project、Case、Claim、Evidence、Timeline、Preset 与 Agent 可用性投影；
- Case 到 Agent 的交接不把问题写入 URL 或浏览器持久存储；
- 公开内容、错误响应和 Agent 响应遵守脱敏与禁止缓存边界。

### Agent Turn

- 唯一生命周期执行 claim、Goal 解析、Plan 编译、能力执行、公开投影和一次性 settlement；
- 支持作品集解释、比较、推荐、通用知识、跨域综合、安全社交输入与 typed Clarification；
- 相同 `requestId` 支持幂等终局重放；确定性 Portfolio Turn 精确重放并保留可用的 opaque ContextHandle，Provider 派生的 General/Conversational 正文只在首次响应返回，同 requestId 重试得到固定 `CAPABILITY_UNAVAILABLE/REPLAY_BODY_NOT_RETAINED`（“该回答未被保留，请重新提问。”）且不再次调用 Provider；主动取消与 deadline 采用一次性终局，迟到结果不得提交；
- 推荐未指定数量时使用安全默认值，合法有界数量直接执行，不因未点名候选而强制澄清；
- Clarification 保存最小 typed blocked Goal，不持久化原问题；Challenge 一次消费，同字段不得重复澄清；
- Clarification V5 在执行前按 requestId 短期预约，只有 terminal settlement 事务才能消费；失败、取消或预约过期不产生半消费终局；
- Goal Interpretation 与 General Knowledge 的固定 system prompt 随 JAR 发布并在启动时无条件校验；General 生产 Validator 按 CONCISE/STANDARD/DETAILED 强制 2/4—6/8 句、逐句中文字符、闭合语义 aspect、Comparison 请求 pair 精确相等，以及 typed caveat 的语言/去重边界；Provider 自报 aspect 不能替代真实正文质量验收；
- Portfolio Fact 与 cross-domain 使用同一闭合 depth：depth 会改变 overview 检索 profile、候选上限、必需 coverage 和公开区块/detail；澄清恢复保留该 typed depth，缺必需公开证据时只形成 PARTIAL。Portfolio comparison 只接受 ARCHITECTURE、IMPLEMENTATION、OUTCOME、RISKS、VERIFICATION 五种后端枚举维度；
- Goal 的 requestedOutputs 不再保存为独立下游权威；它必须与 typed parameters 精确一致，并在 Plan 编译时从 typed intent 重新派生。Reviewed Preset 的 outputs 同样由实际 facet 派生；
- Portfolio Recommendation 只接受当前公开目录派生的 `CAREER_TRACK_*` / `CAPABILITY_*` 约束；requestedSize 与约束进入 Bundle/PostgreSQL 候选元数据、语义排序和 coverage，未满足项公开为 `unsatisfiedConstraints`。Comparison 按闭合 dimension 对齐主体 Claim 与公开来源；
- `AgentRuntimeReadiness` 在启动期将每个 ENABLED Operation 的 `providerRef` 精确绑定到唯一 Transport 的 `ModelProviderKind`，并将 `goal.proposal.v5`/`general.draft.v2` 精确绑定到对应生产 Codec；错配启动失败，Goal/General Bean wiring 与公开 availability 只消费该冻结快照；
- STANDARD 自由文本只接受 AI 提出的 closed SemanticRoute，后端验证 Goal、公开主体、数量、约束与候选范围；原推荐/数量/比较/约束/指代 NLP fallback 已物理删除，模型关闭时自由文本明确不可用；
- 页面 `subjectHint` 经当前公开目录解析为 trusted `defaultSubject`；STANDARD 单主体 Portfolio/跨域省略表达由后端绑定 `SURFACE_HINT`，显式公开主体仍可覆盖默认。AudienceRole 进入所有 task，General Provider 接收闭合角色，Portfolio 仅在相同证据范围内调整 facet 优先级；
- Session V7 保存上一成功 Portfolio Turn 的短期、无正文 typed semantic state，并与终局原子结算；PostgreSQL 只保存独立 AES-GCM envelope。Goal v5 只有在 Provider 返回属于该状态的显式 `recentReference.goalId/sectionId` 后才允许后端注入 `RECENT_TURN`，模型漏 subject 不会自动继承旧主题；
- Discussion 的 `NEEDS_CLARIFICATION` 不再退化为解释不可用：active pointer 生成五种服务端闭合 facet 的短期加密 challenge，expired pointer 只生成重进选择；澄清结算使用 pointer generation guard，选择后由后端构造锁定项目的 deterministic Goal，不重新解释原访客文本；
- 非快速路径 Conversational 的 Provider 正文在进入公开 Turn 前受运行时校验：最多 160 字、以中文为主体、拒绝完整英文句、控制字符和较长访客输入的连续复述；固定快速问候仍由服务端文案处理；
- Recommendation item 携带后端生成的 ENTER_RESULT action；ProjectDiscussionContext、Conversation active pointer 与 V4—V7 State 是当前项目焦点及短期 typed 续问状态的唯一权威，CONTINUE 已闭合为 ENTER_RESULT、ROUTE_IN_CONTEXT、EXIT_CONTEXT、REENTER_SUBJECT；
- 当前项目焦点支持卡片进入、受限候选切换、显式退出、过期重建与刷新恢复；页面只恢复 typed focus，不恢复聊天消息，handle 与 resultItemId 不进入 URL 或浏览器持久化；
- Session V6 复用单调 revision 投影每次 pointer 变更；成功 Turn 与 replay 返回当前权威 discussion summary，前端按 revision 单调消费，不再用热路径二次 GET 推测状态；
- 前端 pending、failure、draft 与 notice 按本地 session 隔离；同标签页并发、失败重试、同 requestId replay 与 active cancel 已通过联合 Exit Gate。

### 生产保护

- 每来源速率与并发限制、单实例 Active Turn 上限和单 Turn 任务并行上限均有独立边界；
- Turn 使用覆盖 Goal、Planning、Execution、Projection 与 Settlement 的 absolute deadline；各子操作受自身上限和剩余预算共同约束；
- `429 RATE_LIMITED` 同时返回 `Retry-After` Header 与 `retryAfterSeconds`；
- 来源地址只做进程内匿名 HMAC，不保存原始地址；
- 外部模型无自动重试和跨 Provider 重发，完整响应体也受 operation timeout 约束。
- DeepSeek/GLM 分别使用带版本的独立请求 Profile；当前两家批准的 structured JSON、thinking disabled 与 non-streaming 字段各自受完整 payload 测试约束。Transport 在读取期限制响应体为 256 KiB，并将鉴权、限流、5xx、非法 JSON 与 envelope 错误投影为 closed diagnostics，Provider 原始响应不进入诊断。
- 未接线的 Portfolio 模型表达端口、编译器和 4 秒幽灵预算已删除；Portfolio 继续使用确定性 presentation，并受 Turn 剩余预算与数据库 3 秒上限约束。Goal/General Provider Codec 拒绝合法 JSON 后的 trailing token。
- Portfolio Fact 按 `AnswerSectionType` 合并同类事实与全部实际来源，不再逐 Claim 生成碎片 section；Cross-domain 关系段由 General mechanism 和闭合 Claim category 生成，并保留 General caveat 作为适用边界。该确定性表达不扩大公开证据范围。

### 短期状态

- `POSTGRESQL` 是标准本地与生产模式；`IN_MEMORY` 用于快速开发和测试；`DISABLED` 是只读浏览模式；
- Context schema 固定为 `agent_context`，由 Flyway 管理；
- Challenge 使用 5 分钟 absolute TTL；Project Discussion 默认 20 分钟；Conversation、其他 Continuation Context、Replay 与终局记录使用 30 分钟 absolute TTL，读取不续期；
- Token 与 payload 分别加密，当前密钥与 previous-key 窗口受配置约束；
- 浏览器仅在当前标签页 `sessionStorage` 保存一个 ResumeToken，不保存问题、回答或会话历史。

## 默认配置

- `local` Profile 默认使用 PostgreSQL Agent State，启动器只检查数据库 readiness；
- `prod` Profile 强制使用 PostgreSQL，配置不完整时失败关闭；
- 模型操作、本地检索、公开数据库读取、治理导入和前端诊断按各自开关显式启用；
- 普通本地开发不要求 Provider Secret，真实模型只在策略审批和显式启用后运行。

当前预算基线为：Turn 20 秒，其中预留 2 秒 settlement；Goal Interpretation、General Knowledge 与数据库操作分别受 8 秒、10 秒和 3 秒上限约束；确定性 Portfolio 执行受 Turn 剩余预算约束；前端等待 25 秒，lease 为 35 秒。
