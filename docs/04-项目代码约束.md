# 实习作品集 Agent：项目代码约束
<!-- DOCUMENT_STATUS: CURRENT_AUTHORITY -->

> **核对日期：** 2026-08-19
> **适用范围：** 生产代码、测试代码、构建脚本、运行配置与后续功能开发
> **实施状态：** 当前 `turn` 已是运行时单一权威；剩余 `turn ↔ answer` 物理依赖按已批准计划迁移，不能扩张为新双栈。

## 目的

本规范保证作品集、Agent、短期状态和内容治理在继续演进时仍有单一权威、明确隐私边界和可复现验证。实现与本文冲突时，必须以已批准设计和新鲜证据决定修正规范或实现，不能静默绕过。

## 基础技术与交付

- Java 21、Spring Boot、Maven；
- Vue 3、TypeScript、Vite；
- JUnit、Spring Boot Test、Vitest、Vue Test Utils、Playwright；
- PostgreSQL 16/pgvector 与 Flyway；
- 生产交付保持一个可执行 JAR 和一个 Docker 镜像；
- 公开运行时只能读取已审核公开 Bundle 或其受控公开数据库投影。

## Java 规则

生产代码和测试代码都禁止：

- 使用 `var`；
- 引入 Lombok 或其数据类注解；
- 使用字段注入；
- 用包含大量依赖或业务行为的 Controller 基类复用代码；
- Controller 直接访问 Repository 实现或数据库基础设施；
- API 返回基础设施对象、内部状态对象或私有源对象。

`record` 只允许用于纯不可变数据载体。包含复杂不变量、生命周期、领域行为、权限语义或预期持续演化的对象必须使用显式不可变类。集合、数组和可变值必须在边界处防御性复制。

类型名、方法名与字段名使用英文；项目业务注释默认中文。注释解释权威、原因、不变量、安全和失败语义，不逐行翻译 getter、mapper 或显然控制流。

## Agent 单一运行权威

唯一运行链是：

```text
AgentTurnRequest
→ Command
→ Goal
→ SemanticPlan
→ SemanticTurnEngine
→ typed Capability
→ SemanticResult
→ PublicAgentTurn
→ Settlement
```

边界要求：

- `turn.api` 只负责 HTTP DTO、认证头解析、准入和错误投影；
- `turn.lifecycle` 是 claim、执行、公开投影和一次性 settlement 的唯一生命周期；
- `turn.planning` 负责 Goal 与 Plan，不执行 Provider、SQL 或状态写入；
- `turn.execution` 执行有界 DAG，Task 不得自行提交会话状态；
- `turn.capability` 通过 typed Port 承载 Portfolio、General 与 Cross-domain 能力；
- `turn.projection` 是内部语义结果到 closed `PublicAgentTurn` 的唯一公开投影；
- `turn.state` 保存经过批准的短期状态，不解释业务输入；
- 模型与数据库 Adapter 只能实现端口，不能成为第二个编排器。

四条无版本 `/api/agent` 资源是唯一公开 Agent HTTP 表面。不得增加版本化兼容入口、第二套 Lifecycle、第二个 replay 缓存或影子状态机。

旧 `answer` 包是迁移中的物理债务，不是生产权威：

- 不得在其中新增 Agent 行为；
- 新 `turn → answer` 或 `answer → turn` 依赖禁止进入；
- 迁移必须按 Replacement Slice 纵向完成：新实现进入生产路径时同期删除旧实现；
- 在双向依赖归零和最终门禁通过前，架构状态保持 `IN_PROGRESS`。

## 模块依赖

- `common` 不依赖 `portfolio`、`turn` 或迁移中的 `answer`；
- `portfolio` 负责公开内容领域、读取、校验与发布投影，不依赖 Agent；
- `turn` 可以依赖 `common` 与公开 `portfolio` 端口，不得读取私有治理源；
- 通用模型基础设施不依赖具体 Goal、Task 或公开 UI；
- PostgreSQL Adapter 实现 typed Port，领域和生命周期不依赖 JDBC 类型；
- 前端只消费公开 DTO，不复刻后端 Goal、Plan、Provider 或状态机。

循环依赖、跨模块实现类 import、为了通过编译而新增的桥接 DTO 和配置式双栈均禁止。

## PostgreSQL 短期 State

标准本地与生产使用 `POSTGRESQL`；`IN_MEMORY` 仅用于快速测试、轻量开发和专项排障；`DISABLED` 表示只读浏览，不能伪装成可用 Agent。

允许持久化：

- request claim、fingerprint、lease 和终局；
- 最终公开 `PublicAgentTurn` replay；
- Conversation 与 ResumeToken 绑定；
- typed Continuation Context；
- typed Clarification Challenge、blocked Goal 和消费状态。

禁止持久化：

- 原始问题与完整 `ConversationWindow`；
- Prompt、模型原始响应和内部 `SemanticResult`；
- 原始 Evidence、查询向量、分数和候选；
- 原始来源地址、Cookie、Header 与凭据；
- 长期聊天记录或用户画像。

Challenge 使用 5 分钟 absolute TTL；Conversation、Context、Replay 与终局使用 30 分钟 absolute TTL。读取、刷新、重放和 Token 轮换都不得续期。schema 固定为 `agent_context`，迁移由 Flyway 管理；解密失败、版本不符和过期状态失败关闭。

Token key 与 payload key 必须独立。previous key 的保留窗口覆盖 TTL 和清理延迟。日志不得包含 Token、密钥、加密 payload 或恢复凭据。

## 准入、deadline 与错误

- 每来源速率、每来源并发、单实例 Active Turn 和单 Turn Task 并行分别受独立限制；
- 来源地址仅用于进程内 HMAC，不能记录或持久化原始值；
- Turn absolute deadline 从 claim 成功开始，覆盖 Goal、Planning、Execution、Projection 与 Settlement；
- 子操作使用自身上限与 Turn 剩余时间的较小值；
- deadline、用户取消和正常完成只能有一个终局；迟到结果不得覆盖；
- 限流统一公开为 `429 RATE_LIMITED`，并让 `Retry-After` Header 与 JSON `retryAfterSeconds` 来自同一计算；
- 错误响应使用封闭 code、稳定 message、retryable 和可选 retryAfterSeconds，不泄露异常、路径、数据库或 Provider 响应；
- 成功与错误响应均使用 `Cache-Control: no-store`。

## 模型与检索

模型操作默认关闭，只有显式配置、数据策略审批和 Provider Secret 同时满足时才启用。

- 单操作最多一次非流式调用；
- 不自动重试，不跨 Provider 重发；
- 结构化响应必须完整读取、解析和校验，正文读取也受 deadline；
- 模型不得决定 Task、DAG、Provider 或扩大公开主体；
- 失败草稿整体丢弃，并按能力合同返回安全降级或明确失败；
- 普通 CI 禁止真实外部 Provider；真实探针需要显式授权。

本地公开检索只使用固定并校验过哈希的模型与已审核公开发布物。候选提供方不能提交可直接信任的派生索引；发布端必须复现批准的 canonical RAG 字节后再派生索引。

## 前端结构与浏览器状态

前端按页面、feature、共享 UI 和数据访问分层。页面负责组合，feature 负责业务交互，API 层负责传输与 closed contract 校验。

Agent 前端要求：

- pending、failure、draft 和 notice 归属具体本地 session；
- 每个 session 最多一个 pending，同标签页总并发受前端上限保护；
- 失败、超时与取消轮次不进入 `conversationWindow`；
- 同 `requestId` 重试复用后端 replay 权威；
- 澄清卡只消费后端 SuggestedAction 或已发布 QuestionPreset，不在叶子组件硬编码业务问题；
- 来源定位从公开 section 和 source key 推导，不引入后端私有字段。

浏览器只允许在当前标签页 `sessionStorage` 保存一个短期 ResumeToken。不得持久化问题、回答、消息历史、Context、Challenge、requestId 历史、Evidence、Prompt 或模型输出。Token 只通过 Bearer Header 发送；不得进入 URL、请求正文、日志或诊断事件。

## 公开内容与发布

- 运行时公开事实以严格加载的发布包为准；
- 只有 `publicStatus = APPROVED` 的 Evidence 可公开；
- Project/Case 主体显式且互斥，未知主体失败关闭；
- canonical payload、Approval、decision ledger、Preset contract set、checksums 和检索派生物必须属于同一 release；
- 发布、激活、回滚和治理导入均为显式操作，不得由应用启动隐式执行；
- 私有治理库、原始 Markdown、候选包和本地模型不得进入公网制品。

详细合同见 `docs/05-公开发布包契约.md` 和 `docs/06-公开内容发布运行手册.md`。

## 安全与隐私

- 不得读取或打包私有 Obsidian、日报、凭据、未审核截图或候选审核状态；
- 不得记录请求体、回答正文、Prompt、Provider 原始响应、Token、Handle、向量或检索候选；
- 诊断事件使用封闭 schema，拒绝任意元数据、URL、Header、堆栈和正文；
- 首页到 Agent 的 handoff 使用随机、短时、内存中、一次性 ID；
- 任何外部调用、发布、部署或真实 Provider 验收均需要对应授权。

## 测试与发布门

- 行为变更遵循 RED、GREEN、REFACTOR；
- API 改动必须有合同测试；
- 时间与 TTL 测试使用可控 Clock 或缩短配置，不等待生产时长；
- State 行为必须同时通过内存合同测试和 PostgreSQL/Testcontainers；
- 前端覆盖成功、加载、空、失败、超时、取消、澄清、重放和会话隔离；
- packaged-JAR 验收覆盖桌面和移动端真实资源；
- 声明完成前运行受影响测试、构建、隐私、文档、质量、架构和发布门；
- 真实 Provider 与生产级外部环境证据不能由 Fake 或局部单元测试替代。

## 自动检查

- `code-quality-check.ps1` 阻断 `var` 与 Lombok；
- `architecture-check.ps1` 和依赖测试阻断非法模块方向；
- `documentation-check.ps1` 对照当前路由、manifest、文档状态和演进日志；
- `privacy-check.ps1` 扫描公开制品与生产源码；
- `verify-release.ps1` 编排最终发布证据。

record、注释质量和领域边界依赖代码审查与针对性测试，不使用无法理解业务语义的字符比例或全路径正则代替判断。

## 变更规则

改变 Command、Goal、Plan、SemanticResult、PublicAgentTurn、API、State 或前后端共享合同的变更，按 `docs/16-Agent单权威持续收敛范式.md` 分类。Level 3 必须先有批准设计和计划，再执行删除完整的 Replacement Slice。

文档、代码和机器状态必须同步。存在开放 Exit Gate、物理依赖或延期证据时，不得把架构或发布状态标记为完成。
